# 퇴계원IC 기본 제어기 데이터 수집

**모델 학습은 실행하지 않습니다.** ego 한 대가 SUMO IDM 종방향 제어기와 LC2013 차선 변경 모델로 주행하는 기록입니다. 사고/정체를 포함할 수 있으며 전문가 데이터로 보증하지 않습니다.

## 실행 및 교통 설정

```powershell
python scenarios/toegyewon/collect.py --repeats 2 --seed 200
python scenarios/toegyewon/collect.py --validate <결과폴더>
python scenarios/toegyewon/summarize_collection.py <결과폴더>
```

`collection_config.json`에 수집용 조건이 있습니다. 기존 도로와 GUI용 교통 설정은 덮어쓰지 않고 에피소드별 route 파일을 만듭니다.

- 경로: 북서 본선→하단 루프→동쪽 금강로 / 남쪽 본선→상단 루프→서쪽 금강로.
- 교통량: 기준 2,920대/시간 × 0.6 / 1.0 / 1.4 = **1,752 / 2,920 / 4,088대/시간**. 수요 설정값이며 실제 삽입률과 다릅니다.
- 배경 분포: Krauss 35%, IDM 승용차 25%, EIDM 20%, ACC 15%, IDM 버스 5%.
- ego는 90초에 한 대만 투입하며 최대 300초 동안 기록. 스텝 간격 0.2초.
- 기본 실행: 3개 교통량 × 2개 경로 × 2회 = 12 에피소드. SUMO 시드는 에피소드마다 다릅니다.
- `results/dataset_한국날짜_시간/`에 저장. 기존 결과가 있으면 덮어쓰지 않습니다.

## 저장 항목

| 파일 / 항목 | 의미 |
| --- | --- |
| `dataset.npz`: obs, next_obs | 각각 N×54 관측 벡터 |
| action_applied | N×2: 실제 속도 변화량/0.2초(m/s²), 같은 도로 구간 내 차선 인덱스 변화량 |
| action_valid | N×2 유효성 마스크. 도로가 바뀌면 차선 번호 변화는 행동으로 해석할 수 없어 두 번째 값 False |
| reward | 주행 거리 근사 보상 − 시간 비용 − ego 충돌 패널티 + 완주 보너스 |
| terminated / truncated | 도착·충돌에 의한 종료 / 시간초과·텔레포트·기타 소실에 의한 중단 |
| next_obs_valid | ego가 사라진 종단 스텝이면 False. 이 경우 next_obs의 0은 결측용 값 |
| episode / t | 에피소드 번호와 에피소드 내 스텝 번호 |
| detected_xy / detected_offsets | 반경 50m 내 차량의 절대 좌표를 가변 길이 배열로 저장 |
| `transitions.jsonl.gz` | 위 전이와 함께 전체 차량의 현재/다음 privileged simulator state 저장 |
| `manifest.json` | 조건, 경로, 시드, 결과, 원본 네트워크 해시 |
| `quality_report.json` | 완주/시간초과 및 일반 차량 텔레포트·급제동 경고. warmup 경고 포함 |
| episode별 route / lanechanges / warnings | 실제 투입 설정, SUMO 차선 변경 로그와 경고 |

NPZ는 `numpy.load(path, allow_pickle=False)`로 읽습니다. `done = terminated | truncated`입니다. 종단 결측 관측 및 invalid action은 반드시 마스크를 적용해야 합니다. 시간초과의 next_obs가 유효하면 학습 알고리즘에 따라 부트스트래핑 대상으로 쓸 수 있습니다.

## 관측 54차원

앞의 6개 값은 ego 속도/33.33, sin(방향각), 차선 정규화 인덱스, 현 도로 끝까지 거리(200m로 정규화·상한 1), 목표 경로 one-hot 두 값입니다. 그 뒤 가까운 8대 각각에 대해 상대 x/50, 상대 y/50, 상대속도/33.33, 상대방향 sin·cos, 존재 여부를 기록합니다. 없는 차량 슬롯은 0으로 채웁니다.

반경 50m의 이상적인 평면 센서를 가정합니다. 고가·하부도로의 높이 차이, 가려짐, 센서 잡음은 반영하지 않았으므로 높이가 다른 도로의 차량도 관측될 수 있습니다. 전체 state는 검증용으로만 쓰고 정책 입력에 몰래 포함하면 안 됩니다.

## 행동과 보상 해석

기본 제어기의 내부 명령을 읽는 것이 아니라 **시뮬레이션에서 실제로 실현된 움직임**을 저장합니다. 따라서 `action_raw`라는 이름을 사용하지 않으며 기존 `train_bc.py`에 그대로 넣을 수 없습니다. 추후 이 데이터로 제어 정책을 학습하려면 실제 가속도와 제어 명령의 차이, 마스크, 관측 차원을 반영하는 어댑터가 필요합니다.

보상은 `0.01 * speed_t * dt - 0.001 * dt - 5 * ego_collision + 2 * arrival`로 사후 계산합니다. 현재 제어기는 이 보상을 최적화하지 않습니다. 기존 고속도로 학습 보상과도 동일하지 않습니다.

## 데이터 품질과 분할

높은 수요에서 시간초과 또는 일반 차량의 텔레포트가 발생할 수 있습니다. 모든 기록을 보존하고 품질 보고서에서 구분합니다. 도착만 했다는 이유로 무조건 좋은 시범 주행이라고 판단하지 마세요. 첫 모방학습 후보를 고를 때는 완주와 경고 유무를 함께 확인하고, 정체·실패 기록은 별도 분석에 사용하세요.

훈련/검증/시험 데이터를 나눌 때 **스텝을 무작위로 섞지 말고 에피소드 단위로 분리**해야 합니다. 인접 스텝이 서로 다른 분할로 들어가면 평가가 낙관적으로 보일 수 있습니다. 현재 수집만 수행했으며 학습·평가 분할과 모델 학습은 하지 않았습니다.

## 용량 및 팀 공유

NPZ와 manifest·품질 요약은 저장소의 `datasets/baseline_v1/`에서 공유합니다. 큰 전체 상태 JSONL 및 상세 로그는 로컬 `results/`에 보관합니다. JSONL에는 SUMO 시뮬레이터 데이터만 들어 있으며 실제 차량의 개인정보를 수집한 것이 아닙니다. 수업 최종 제출에서 요구하는 학습 모델 주행 데이터와 외부 데이터셋 게시까지 완료했다는 뜻은 아닙니다.
