# Ego 없는 교통 안정화 — 2026-10-31

## 현재 실행

`open_sumo.cmd` 또는 `python scenarios/toegyewon/traffic.py --gui`로 실행합니다. 직접 SUMO를 열 때는 `traffic/traffic.sumocfg`를 선택합니다.

- ego 없음. 30분 동안 교통 투입 + 최대 10분 배출, 0.2초 간격.
- 기본 수요 2,920대/시간. 낮음 1,752, 높음 4,088대/시간으로도 검증.
- Krauss 35%, IDM 승용차 25%, EIDM 20%, ACC 15%, IDM 버스 5%. 비율은 실측값이 아닌 실험 설정.
- 비교를 위해 차량별 종류·출발 요청을 고정 생성. 목표 속도 배율 1, 속도 배율 분산 0.
- LC2013 협조 차선 변경 사용. 위반 차량과 ego 긴급 회피 감독기는 사용하지 않음.
- 안전 간격·충돌 검사 유지, 순간이동은 꺼짐. 차가 막혀도 강제로 없애서 성공 처리하지 않음.
- 기존 도로 형상·차선 수·입체 연결·실선 변경 제한과 표시를 유지.

## 원인과 수정

기존 두 금강로 합류부는 램프가 무조건 양보하는 priority 연결이었다. 같은 교통 수요로 40분을 실행해도 램프 대기열이 해소되지 않는 경우를 재현했다.

금강로 동쪽 `7461635551`, 서쪽 `1810880137`만 zipper로 바꾸었다. 합류 지점의 차량들이 서로의 접근에 맞춰 속도를 조정한다. 제어기 자체를 새로 만들거나 안전 간격을 무시하는 TraCI 명령을 추가하지 않았다. 합류 가시거리는 80m로 설정했다.

netconvert가 만든 완전한 해당 합류 블록만 반영한다. 재생성이 엇갈림 구간 길이와 실선 제한을 부수적으로 바꾸는 것을 발견하여, 다른 도로·차선은 원본과 XML 내용까지 동일하게 유지하도록 검증한다. 충돌 관계 행렬을 수작업으로 만들지 않는다.

이는 **협조 합류를 가정한 시뮬레이션 안정화 설정**이다. 실제 퇴계원IC가 항상 교대로 합류한다는 주장이 아니다. 실제 가속 차로 길이·우선권·관측 교통량과의 보정은 남아 있다.

## 검증 결과

같은 수요 파일로 기존 priority와 새 zipper를 각각 3개 교통량 × 5개 시드(1000~1004), 총 30회 비교했다. 제어기 시범 데이터 수집이나 BC/PPO 학습은 실행하지 않았다.

| 교통량 | 설정별 투입 요청 합계 | 기존 미완료 | 새 설정 미완료 | 새 설정 충돌 / 순간이동 |
|---|---:|---:|---:|---:|
| 낮음 0.6 | 4,390 | 0 | 0 | 0 / 0 |
| 기준 1.0 | 7,300 | 343 | 0 | 0 / 0 |
| 높음 1.4 | 10,220 | 1,679 | 0 | 0 / 0 |

새 설정은 **21,910대 모두 도착**, 미출발 잔여도 0이다. 기존과 새 설정 모두 동일한 2,400초 상한과 순간이동 해제 조건이다. 따라서 이 차이는 단순히 실행 시간을 더 준 효과가 아니다.

기존 램프 경로의 평균 정지 시간은 기준 교통량에서 약 507~517초, 높은 교통량에서 562~719초였다. 새 설정에서는 해당 경로의 SUMO waitingTime이 0초였다. 이는 정지 기준 아래로 멈추지 않았다는 뜻이며 감속·지연이 전혀 없다는 뜻이 아니다. 기존 미완료 차량의 대기는 종료 시점까지의 값으로 실제 대기보다 짧게 측정될 수 있다.

**남은 문제:** 새 설정에도 급제동 경고가 낮음 1회, 기준 92회, 높음 219회(각 5개 시드 합산) 발생했다. 312회 모두 ACC 차량이며 주로 `86198728_0`, `52873356_0` 분기 접근부다. 도로 흐름의 교착 해소와 승차감 검증은 구분한다. 아직 모델 학습용 전문가 행동으로 인증한 환경은 아니다. 이 실험은 실측 보정이나 실제 안전성을 입증하지 않는다.

## 도로별 행동을 달리하는 방법

1. **도로 연결과 합류 규칙:** 이번에 적용했다. 같은 제어기도 합류부의 이웃 차량과 우선권에 맞춰 다르게 반응한다.
2. **차량 성향:** vType에서 tau, accel/decel, lcCooperative, lcStrategic 등 조정 가능. 모든 모델이 같은 파라미터를 같은 뜻으로 사용하는 것은 아니다.
3. **구간별 정책:** 필요하면 TraCI로 특정 구간 진입·이탈 시 성향을 바꾸고 복원할 수 있다. 이번에는 적용하지 않았다. 모델 자체를 갑자기 교체하기보다는 기본 제어기와 도로 규칙부터 검증하는 편이 비교 해석에 유리하다.

## 재현과 저장

```powershell
python scenarios/toegyewon/traffic.py --validate
python -m unittest discover -s scenarios/toegyewon -p "test_*.py"
```

- traffic_config.json: 실행 시간, 합류 설정, 모델 비율, 검증 조건
- traffic/network.net.xml, routes.rou.xml, traffic.sumocfg: 공유 실행 파일
- traffic/network_audit.json: 외부 차선 형상·길이 및 연결 보존 검증
- traffic/validation.json: 회차별 완료·충돌·경고 및 경로별 지연
- 로컬 results/traffic_stability_*: 원시 tripinfo, 충돌, 요약, 실행 로그. 학습용 데이터셋이 아닌 진단 결과.

기존 baseline_v1, rules_v2, controller_comparison 학습 데이터는 현재 브랜치에서 삭제했다. 로컬 원본과 구형 실행 로그는 휴지통으로 이동했으며 Git 과거 이력은 유지한다. 지도 증거와 수업 원본 샘플 데이터는 보존했다.
