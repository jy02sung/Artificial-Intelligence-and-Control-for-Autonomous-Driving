## 실제 자료와 재현 범위

2026-10-31 네이버 위성지도(정보 보기 해제)에서 중앙 엇갈림, 북쪽 분기, 남쪽 합류, 금강로 서측, 본선 교량을 직접 확인했다.
출처: https://map.naver.com/p/search/퇴계원IC
지도에 표시된 영상 제공처는 국토지리정보원이며 **사진 촬영일은 확인하지 못했다**.
원본 화면 캡처는 로컬 `results/marking_survey_20261031/`에 보존한다. 지도 영상 자체는 공개 저장소에 재배포하지 않는다.

**전 구간 실측 재현이 아니다.** 선 종류는 사진의 육안 해석, 도로 좌표와 차로 수는 기존 OSM 모델이다. 정확한 선 시작점은 근사이며, 가려지거나 확인하지 못한 차선은 `unverified_dashed`로 남긴다. `rules_v2/inventory.json`에는 모든 외부 도로의 확인 상태가 있다. 사진에서 읽은 선 종류와 OSM에 옮기는 위치 오차를 구분해야 한다.

`motorway_north.png`는 이동 중 북쪽 주변 도로가 찍힌 보조 이미지로, 본선 판독 근거로 사용하지 않는다.
다차로 도로 중 미확인 11개 edge는 `1414146965`, `1414146971`, `169728835`, `206426298`, `37927512`, `52873356`, `781184662#2`, `844484877`, `844484878#0`, `844484878#1`, `86198719`이다. 이들 구간까지 실제 지도 기준으로 확정하는 후속 판독이 남아 있다.
화면에서는 `markings.add.xml`의 흰색 노면표시를 겹쳐 그려 실선·점선을 구별한다. 표시와 행동 제한은 같은 inventory에서 생성한다. 점선 길이/간격은 3m/6m의 시각화용 공통 설정이며 실제 도색 규격을 실측한 값은 아니다.
안전지대·중앙분리대·고가도로 간 이동을 허용한 것이 아니다. 위반/회피 예외는 같은 도로의 인접 차로 노면표시만 대상으로 한다.

## 차량 행동

- 일반 차량: SUMO `changeLeft/changeRight` 권한으로 실선 변경 금지. 점선에서는 기존 Krauss/IDM/EIDM/ACC의 종방향 제어와 LC2013 차선 선택을 유지한다.
- 위반 차량: 버스를 제외한 배경 차량 각각을 seed+차량 ID 해시로 5% 확률 배정한다. 주황색으로 표시한다. `custom1`은 실선 변경 허용 표시용 클래스일 뿐, 충돌 무시 설정이 아니다. 경로 선택/속도 이득 등의 기존 LC2013 동기에 따라 변경하며 매 순간 무작위 변경하지 않는다.
- 우리 차량: 빨간색 한 대. 평상시 passenger, 긴급 예외를 요청하는 한 스텝만 custom2. 앞차와의 TTC < 1.5초 **동시에** 현재 긴급제동 능력으로 계산한 정지거리 부족 조건을 요구한다. 최대 제동 요청을 먼저 걸고, 옆 차선 앞 간격 ≥ max(5m, ego속도×1초), 뒤 간격 ≥ max(5m, 뒤차속도×1.5초), 진입할 차선의 경로 여유가 있을 때만 변경 요청한다. 요청 간 대기 5초.
- SUMO 속도 안전 설정 유지. 긴급 변경은 laneChangeMode 512로 안전 간격 검사를 유지한다. 실제로 변경했는지는 요청과 별도로 기록한다.
- 이 규칙은 실험용 단순 위험 판정기다. 전방 추돌 중심이며 측면 충돌·가림·센서 오차·모든 회피 상황을 보장하지 않는다. 법적 예외 판단이나 검증된 자율주행 안전 기능을 의미하지 않는다.

## 실행

프로젝트 루트에서 Python에 sumolib/traci/numpy가 설치된 환경으로 실행한다.

```powershell
python scenarios/toegyewon/build_markings.py
python scenarios/toegyewon/run_rules.py --gui
python scenarios/toegyewon/collect.py --rules --repeats 2 --seed 300
python -m unittest discover -s scenarios/toegyewon -p "test_*.py"
```

`rules_v2/preview.sumocfg`만 열면 도로 표시와 기본 차량만 동작한다. 위반 배정·긴급 회피 감독 기능까지 실행하려면 **run_rules.py**를 사용한다. 네트워크는 기존 파일을 복제하여 별도 생성한다. 기존 baseline 데이터와 원본 SUMO 도로 파일은 그대로 둔다.

## 데이터

새 실행은 매번 `results/rules_v2_날짜시간/`에 저장한다. 교통량 0.6/1.0/1.4배 × 경로 2종 × seed 2개 = 12회, 워밍업 90초, ego 관찰 한도 300초, 간격 0.2초로 기존 조건을 유지한다.

- 기존 54차원 관측과 실제 행동을 유지하고 `rule_context`, `next_rule_context`에 [왼쪽 존재, 오른쪽 존재, 왼쪽 실선, 오른쪽 실선]을 별도 저장한다. 학습 시 이 정보를 쓰려면 관측에 연결해 58차원 모델로 구성해야 한다.
- `emergency_requested`, `emergency_braking`은 요청 여부다. 실제 변경 성공은 rule event 로그 및 행동에서 확인한다.
- JSONL에는 위반 차량 ID 목록, 위험 판단 근거, 현재/다음 도로 규칙, 전체 교통 상태를 함께 남긴다. 위반 차량 ID는 분석용 정답이며 센서로 알 수 있는 정책 입력이 아니다.
- 매 회차 `.rules.jsonl`은 워밍업부터 전체 차량의 실제 차선 변경과 실선 통과, 위반/회피 여부를 기록한다. 일반 차량의 실선 통과는 수집 실패로 검사한다.
- 인위적으로 만든 긴급 상황은 `test_rule_sumo.py`에서만 테스트하며 자연 교통 데이터에 섞지 않는다. 자연 수집에서 회피가 0회이면 회피 학습 데이터가 확보됐다고 해석하지 않는다.
- 아직 AI 학습을 실행하지 않았다. 수집 ego는 SUMO 제어기 + 규칙 기반 감독기다.
