# 위험한 차선변경의 경로 보상 지급 조건 비교

## 관측 근거

미래 분기 안내10만스텝의 교통48회 평가: 완주37·충돌11·기타0. 충돌 직전11건 중9건에서 옆차로 위험1인 변경을 요청했다. 이는 충돌 책임/유형을 직접 판정한 수치는 아니다.

route_11, seed79103을 동일 모델로 재현:62.6초에 위험0.45597인 변경을 실행하면서 선택+유지 보상0.25556, 안전 벌점-0.04560, 전체 보상+0.24996.63.2초 충돌. route_13, seed79102도63.2초 충돌을 정확히 재현했으나 위험한 변경에 경로 보상을 준 사례는 없었다. 따라서 보상 충돌은 일부 사례의 개선 가설이며 전체 원인으로 단정하지 않는다.

## 비교 조건

동일 출발 정책 round-02/route/policy-200000.pt, 동일 도로/HV, 강제 보정 없음. 세 조건 모두 새 관측57:60의 연결 가중치만0으로 초기화해 학습 전 행동분포를 보존한다.

|조건|관측|보상|
|---|---|---|
|safe_reward|기존 관측|변경 위험>=0.2이면 해당 스텝의 양수 목적지 차로 선택·유지 보상만 회수|
|lateral_zero|옆 차로 위험 관측 추가|기존 보상|
|combined|옆 차로 위험 관측 추가|동일 지급 조건 적용|

대조군은 완료된 기존 조건 추가학습. lateral_zero는 기존 lateral과 초기화 효과를 비교한다. safe_reward와combined로 새 관측의 추가 효과, lateral_zero와combined로 보상 지급 조건의 추가 효과를 구별한다. 연결 가중치가 달라져 텐서 해시는 기존 대조군과 같지 않지만, 기존 관측의 해당 칸이0이므로 시작 행동은 동일하다.

위험 기준0.2는 기존 기회 보상의 안전한 변경 판단과 맞췄다. 행동 자체는 차단/변경하지 않는다. 미지급 보상을 나중에 소급 지급하지 않고, 차로 이탈 벌점과 기존 안전 벌점은 유지한다. 추가20만스텝, seed11, 중간0/51200/100352/151552/200000 평가. 개발 평가79101~79103, 교통48회/무교통16회. 개선 후보는 미사용seed 검증을 별도로 거친다.

## 구현 및 검증

1. 양수 경로 보상만 정확히 회수하고 안전한 상태/이탈 벌점에는 영향이 없는 단위 검사를 작성한다.
2. 독립 환경과 실행기를 추가하고 보상 회수 횟수·총량, 원래 안전 벌점, 완주·충돌·기타를 기록한다.
3. 새 입력 초기화는 출발 모델 로딩 때만 적용한다. 기존 행동 보존/학습 가능성 검사를 재사용한다.
4. 짧은3조건 학습·평가, 해시/입력 동일성 검사를 통과한 뒤 조건별로 실행한다. 처음 활성 CPU 작업6개에서 시작했고,7개 실행 시 학습별 약28~31스텝/초와 CPU57~65%를 확인해8개까지 확장 시험했다. 각 PyTorch 프로세스는1스레드를 유지하고 총 처리량과 오류 여부를 점검한다. CPU 사용률만으로 속도 향상을 확정하지 않는다.
