# 조원용 후속 실험 · 전진, 경로 이탈, 분기 보상의 조합

M0에서 가장 많았던 실패는 일반 시간초과 642건과 실제 경로 이탈 512건이었다. 변경이 필요한 출발에서는 세 시드 모두 0/208이었다. 같은 M0에서 출발해 전진 보상을 키우면 어느 실패가 완주로 바뀌는지, 실제 이탈 벌점을 키우면 어느 실패로 옮겨 가는지 확인한다. 이미 배정한 완주·분기·충돌 단독 조건은 그대로 재사용한다.

| M0 학습 시드 | 완주 | 충돌 | 실제 이탈 | 끝 정지 | 일반 시간초과 |
|---|---:|---:|---:|---:|---:|
| 11 | 71 | 93 | 160 | 5 | 247 |
| 22 | 112 | 50 | 186 | 20 | 208 |
| 33 | 94 | 107 | 166 | 22 | 187 |

시드별 분모는 576회다. 세 시드가 동일한 576개 상황에서 주행했다. [평가 원자료](../../results/jys3_ppo_clean_ladder) · [기존 단독 조건 배정표](jys3-m0-single-reward-handoff.md)

## 담당과 우선순위

| 순서 | 담당 조건 | M0에서 바꾸는 값 | 비교 대상과 판정 질문 |
|---|---|---|---|
| 1 · 독립 | `progress` | 경로 전진 누적 상한 +2 → +6 | M0와 비교해 일반 시간초과 → 완주가 늘어나는가? 시간초과 → 충돌·이탈도 함께 센다. |
| 1 · 독립 | `off_route` | 실제 이탈 −5 → −8 | M0의 이탈이 완주로 바뀌는가? 이탈 → 끝 정지·일반 시간초과 전환과 변경 필요 출발 완주도 본다. |
| 2 · 조합 | `arrival_fork` | 완주 +10, 분기 +2.5 | 완주 단독에 분기 보상을 추가한 효과와 M0에 분기 보상을 추가한 효과를 비교한다. |
| 3 · 선택 조합 | `fork_off_route` | 분기 +2.5, 실제 이탈 −8 | 올바른 분기 보상에 이탈 벌점을 더하면 변경 필요 출발의 완주가 더 늘어나는가? 이탈 감소와 정지 증가를 함께 본다. |

두 명이면 독립 조건을 하나씩 맡는다. 추가 슬롯 하나면 기존 두 조원의 결과를 모두 활용하는 `arrival_fork`를 먼저 실행한다. 네 조건은 각각 무작위 초기화하므로 병렬 학습할 수 있다. 조합 판정은 단독 조건의 평가 JSON이 도착한 뒤 수행한다. 새 조건당 3시드 × 25만 스텝, 선정 1,920회, 홀드아웃 1,728회다.

## 바로 실행

Python 3.10과 팀 SUMO 환경에서 새 폴더에 체크아웃한다. 팀 실험 버전은 PyTorch 2.14.0, NumPy 2.2.6, libsumo·TraCI·sumolib 1.27.1이다. M0 기준선과 세 시드의 초기 해시는 이 브랜치에 포함돼 있다.

```powershell
git clone --single-branch --branch experiment/jys3-m0-reward-followup https://github.com/jy02sung/Artificial-Intelligence-and-Control-for-Autonomous-Driving.git m0-reward-followup
cd m0-reward-followup
$arm = 'progress'
python -m utils.jys3_m0_single_reward $arm --check
python -m utils.jys3_m0_single_reward $arm --workers 4
```

`$arm`에는 담당 조건 하나를 넣는다. 한 PC에서 두 조건을 동시에 실행하면 조건당 `--workers 2`로 설정한다. 중단 후 같은 명령을 실행하면 저장된 체크포인트와 평가 조각을 읽어 재개한다.

## 조합 결과 모으기

각 담당자는 `results/jys3_m0_single_reward/<조건>/`의 `protocol.json`, `comparison.json`, `report.md`, 세 시드의 `eval_*.json`을 공유한다. 조합 담당자는 단독 조건 폴더를 같은 경로에 복사하고 아래 명령을 실행한다.

```powershell
python -m utils.jys3_m0_single_reward arrival_fork --summarize
```

`arrival_fork`에는 `arrival`과 `fork` 결과가, `fork_off_route`에는 `fork`와 `off_route` 결과가 필요하다. 실행기는 네 조건의 경로·출발 차로·교통 시드·초기 관측 해시가 일치하는지 확인한다. 각 시드의 **상호작용(%p) = 조합 − 단독 A − 단독 B + M0**를 다섯 종료율과 변경 필요 완주율에 대해 계산한다. 예를 들어 완주 단독이 +4%p, 분기 단독이 +3%p, 조합이 +5%p면 완주율의 상호작용은 −2%p다. 세 시드의 부호와 크기를 함께 보고한다. 각 조건에서 선정한 정책의 성능 차이이므로 학습 과정은 같은 스텝의 128회 결과로도 비교한다.

## 코딩 에이전트에 붙여넣을 프롬프트

```text
담당 조건은 progress다. 이 첫 줄의 조건을 배정받은 이름으로 바꿔 사용한다.
팀 저장소 https://github.com/jy02sung/Artificial-Intelligence-and-Control-for-Autonomous-Driving 에서 experiment/jys3-m0-reward-followup 브랜치를 별도 작업 폴더에 체크아웃하고 docs/experiments/jys3-m0-reward-followup.md에 따라 내 조건 하나를 실행해줘.

1. 실제 코드 커밋을 기록하고 python -m utils.jys3_m0_single_reward 담당조건 --check로 세 시드의 초기 가중치 해시 및 적용 보상표를 확인해줘. M0와 같은 고교통 15,000대/시, 16경로, 50차원 관측, 공유 Critic, γ=0.99로 학습해. 물리 분기와 고가 시야 보정은 켜고 안전게이트는 꺼줘.
2. --workers 4로 시드 11·22·33을 25만 스텝씩 학습해줘. 매 5만 스텝의 동일한 128회 평가로 M0와 추이를 비교하고, 각 시드 선정 모델을 동일한 576회에서 검증해줘. 선정 규칙은 완주 최대, 충돌 최소, 변경 필요 출발 완주 최대, 이른 스텝 순서다.
3. 시드별 576회에서 완주·충돌·실제 이탈·끝 정지·일반 시간초과 건수와 비율, 208회에서 변경 필요 출발의 완주율, M0의 5×5 종료 전환표를 보고해줘. 기존 완주를 잃은 수와 새로 완주한 수도 알려줘.
4. 조합 조건이면 위 문서의 단독 조건 평가 파일을 받아 --summarize로 네 조건의 상호작용을 계산해줘. 단독 조건 자료가 아직 없으면 조합 모델 자체의 성적과 자료가 도착해야 채울 비교를 구분해줘. 담당 폴더의 설정·평가 원자료·보고서를 공유할 수 있게 정리해줘.
```
