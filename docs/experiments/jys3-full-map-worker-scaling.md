# dagger5 전체 맵 수집 워커 비교

같은 정책과 시드 생성 규칙을 유지한 고교통 전체 맵 수집이다. 워커별 준비 주행 32회를 마친 뒤 신규 주행 64회(경로별 4회)의 시뮬레이션·압축·저장·검증 시간을 측정했다. 서로 다른 에피소드를 사용했고 모두 최종 수집에 포함했다. CPU는 psutil이 측정한 시스템 전체 평균이다.

| 워커 | 전이 | 초 | 전이/초 | CPU |
|---:|---:|---:|---:|---:|
| 3 | 22,823 | 61.86 | 368.9 | 32.0% |
| 6 | 22,977 | 42.72 | 537.9 | 56.2% |
| 8 | 22,090 | 38.69 | 570.9 | 69.6% |
| 10 | 23,396 | 38.99 | 600.1 | 81.3% |
| 12 | 23,304 | 40.15 | 580.4 | 81.6% |

공통 시험에서 가장 빨랐던 10개를 유지하고 준비 작업을 최대 3블록까지 겹쳤다. 준비 블록 3개 이후 8블록(128회)에서 46,432전이 / 70.41초 = 659.5전이/초, 평균 CPU 96.1%였다.

재시작 명령은 jys3 작업 폴더에서 `python -m utils.jys3_collect_full_map`이다. pyarrow, libsumo, psutil을 포함한 기존 수집 환경을 사용한다. worker_benchmark.json은 비교 결과와 선정 워커 수를 보존하며, 완료 블록과 개별 주행 파일은 재시작 시 재사용한다.
