# 기존 정책 보존을 위한 학습률 단독 비교

Goal: 관측·보상 조합을 유지하면서 추가학습 중 정책 퇴화를 줄일 수 있는지 독립 비교한다.
Architecture: 현재 anticipatory 조건의 환경·보상·출발 정책·입력 초기화를 그대로 재사용하고, 새 실행 프로세스에서 학습 설정을 읽을 때 learning rate만 변경한다. 실행 중인 파일과 기존 결과는 수정하지 않는다.
Tech stack: PyTorch PPO, libSUMO, Python unittest.

## 근거와 범위

기존 조건 그대로 추가학습한 대조군도 교통 완주가45/48에서 최종39/48로 저하됐다. 새 관측·보상 여러 조건에서도 중간 길찾기 퇴화가 나타났다. 따라서 관측·보상 탐색과 별도로 업데이트 크기를 줄이는 통제 실험1개를 추가한다. 퇴화 원인이 학습률이라고 확정한 것은 아니다.

대조군은 safety_strength_trials/anticipatory의 lr0.0003. 새 조건은 lr0.00003만 다르다. seed11, 추가20만스텝, 동일 초기모델, 옵티마이저 새 시작, 같은 네트워크·클리핑·엔트로피·할인율·관측·보상·교통이다. 신규 입력57:63만0으로 초기화한다. 행동 강제 보정은 없다. 원본 모델은 유지한다.

## 구현 및 검증

- [x] 학습률 변경 함수의 원본 불변성 및 다른 파라미터 불변성을 먼저 테스트한다.
- [x] 별도 wrapper에서 공통 학습기의 설정 읽기만 해당 기본 hp 파일 경로에 한정하여 바꾼다. 실제 사용 hp를 기존 manifest에 기록한다.
- [x] 32스텝 smoke와 초기 텐서 동일성, 환경·보상·입력파일 해시 동일성을 검증한다.
- [ ] CPU 슬롯이 확보되면 추가20만 학습,5/10/15/20만 평가. 기존 anticipatory의 같은 체크포인트·seed와 비교한다.
- [ ] 학습률을 낮춰도 동일하게 실패하면 이 가설을 개선 근거로 채택하지 않는다. 통과 후보만 새seed320회 검증한다.

검증 결과: 테스트2개,32스텝 학습 및4회 짧은 평가 통과. 대조군과 실제 hp 차이는lr0.0003→0.00003 하나뿐이며 초기 텐서·출발 정책·simulation·reward·action_safety·observation_dim 및 모든 교통 입력 해시가 동일하다. 기존 환경 소스 해시도 모두 동일하다.

실행: 보상 억제 단독 조건의20만스텝 모델 저장·해시·CSV를 확인한 뒤 해당 슬롯에서 새 학습을 시작했다. 실제 학습 manifest의lr0.00003과 진행 스텝 증가를 확인했다. 성능 평가는 아직 시작 전이다.
