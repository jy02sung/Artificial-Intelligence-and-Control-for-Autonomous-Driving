# HV 전용 기본교통 진단 — 2026-11-13

## 결론

AV를 전혀 넣지 않아도 합류 대기, 출발 대기, 엇갈림 차로 변경 실패가 발생한다. 원본의 첫 3개 seed는 관찰 시간을 늘리면 모두 빠져나갔지만, 지퍼 합류 시험에서는 다른 seed에서 장시간 교착이 재현됐다. 따라서 “HV는 정상이고 AV만 문제”라고 볼 수 없다. AV 학습과 300m/500m 실험은 계속 중단한다.

## 공통 조건과 재현

- 입력: `results/resume_validation_20261112/traffic_v2/base-hv`의 network.net.xml, highway.rou.xml, run.sumocfg.
- 총수요 10,200대/시간, 차량 유입 0~900초, 최대 관찰 3,600초, simulation step 0.2초.
- 16개 경로, 기존 4종 추종 제어기 혼합, 버스 5%, 승용차 중 custom1 차량 2%를 유지했다.
- SUMO 기본 HV 동작을 직접 실행한다. AV 정책이나 별도 Python 차량 강제 제어는 사용하지 않는다. 따라서 custom1 비율 유지는 별도 위반 행동 제어까지 검증했다는 뜻이 아니다.
- 텔레포트 비활성화. 충돌은 기존 검출 설정에서 확인하며, 별도의 junction collision check를 추가한 시험은 아니다.
- 통과 기준: **모든 경로에서 예정=삽입=도착, 충돌·텔레포트·잔류·미삽입 모두 0**.
- 실행기: `utils/hv_flow_audit.py`, 원자료: `results/hv_flow_audit_20261113/runs/<조건>-<seed>/`.
- `complete.json`, `samples.json`, `tripinfo.xml`, `sumo.log`에 경로별 결과와 위치 근거를 저장했다. 큰 원자료는 로컬에 보존한다.
- 첫 감사 코드 커밋 `938c264`, 입력 기준 커밋 `78c7e84`. 후속 조건은 이 문서와 함께 커밋한 실행기로 재현한다. 입력 파일 해시는 각 조건의 manifest.json에 있다.

```powershell
python -m utils.hv_flow_audit --modes original lane_split recompiled zipper combined --seeds 1001 1002 1003
python -m utils.hv_flow_audit --modes zipper lane_split --seeds 2001 2002 2003
```

완료된 동일 조건/seed는 건너뛴다. 조건을 변경해 재시험할 경우 기존 결과를 덮어쓰지 않고 별도 출력 경로를 사용해야 한다.

## 독립 변경 조건

- **original**: 입력 그대로.
- **lane_split**: 13·14·15번 각 750→200, 16번 750→2,400대/시간. 북쪽 합계와 전체 합계는 동일. 실측 배분이 아니라 병목 진단용 조건이다.
- **recompiled**: 원본을 netconvert로 재생성만 한 대조군.
- **zipper**: 재생성 대조군에 단순 합류 3곳(1808903166, 1000493465, 1810880137)의 junction type만 zipper로 변경.
- **combined**: 수요 배분 변경 + 위 지퍼 합류.

원본 맵·트래픽은 덮어쓰지 않았다. 시험용 입력은 results 아래 별도로 생성했다.

### 재생성 부작용

원본과 재생성 대조군 사이에는 38개 lane의 길이/끝점 형상 및 3개 lane의 acceleration 속성 차이가 있다. 특히 엇갈림 edge 170059994의 길이가 **51.07m→29.32m**로 줄었다. 반면 recompiled와 zipper의 외부 차로 속성 및 외부 연결 튜플은 동일하다. 지퍼의 효과는 재생성 대조군과 비교해야 한다. 이 파일을 최종 맵으로 채택하지 않는다.

## 실패 사례

- combined seed1001: 3600초까지 2387/2550대 도착, 153대 잔류·10대 미삽입. route13.34가 170059994의 차로3 끝에서 약 2949초 대기. 목적지 연결은 차로0~2에 있다. 뒤의 route05 차량은 차로3이 맞는데 앞차 때문에 멈췄다.
- combined seed1002: 2246/2550대 도착, 225대 잔류·79대 미삽입. route14.15가 같은 구간 차로3에서 약 3277초 대기. route05.35는 차로2에서3으로 이동하지 못하고 대기했다.
- zipper 추가 seed2001: 2272/2552대 도착, 111대 잔류·169대 미삽입. route14.94가 같은 구간 차로3에서 약 2459초 대기했다.
- 위 실패에서 충돌은 검출되지 않았다. **충돌 없이도 잘못된 차로의 선두 차량이 전체 흐름을 막을 수 있다.** 3600초 관찰 내 해소되지 않은 교착이며 무한히 지속됨까지 증명한 것은 아니다.

## 적용 판단과 다음 단계

1. 지퍼 합류를 모든 병목의 해결책으로 일괄 적용하지 않는다. 단순 합류의 선두 대기는 개선됐지만 엇갈림 병목은 별개다.
2. 수요 배분 변경은 원본 형상을 유지하는 독립 대안이며, 실측 교통량이라고 발표하지 않는다. 완주하더라도 긴 대기·급제동이 남는지 별도로 본다.
3. 최우선 후속 수정은 **원본의 51.07m 엇갈림 구간이 재생성 시 짧아지지 않게 보존하고**, 동일 수요·seed로 재검증하는 것이다. 이후 HV의 차로 변경 협조/진입 간격을 한 항목씩 비교한다. 순간 차로 이동이나 텔레포트로 통과를 만들지 않는다.
4. 수요가 끝난 후 전부 배출되는 것과 지속 유입에서도 안정적인 것은 다르다. 채택 전 장시간 유입 및 새 seed 검증이 필요하다.
5. AV는 HV 기준이 확정되기 전까지 재개하지 않는다.

정지원인 집계는 5초 간격 상태 분류이다. vehicle-seconds는 사건 수가 아니다. 경로별 mean_wait와 mean_depart_delay는 **도착한 차량 기준**이므로 실패 조건에서는 잔류 차량의 긴 대기를 누락한다. 반드시 잔류·미삽입 수와 함께 해석한다.

## 후속 수정 완료: 원본 형상 보존 + 안정적 HV 운영 조건

이 절은 위의 초기 진단 이후 사용자의 “HV 문제 해결” 요청에 따라 진행한 결과다. AV는 여전히 중단 상태이며 아래 변경은 별도 시나리오에만 적용했다.

### 원인과 수정 순서

1. **재생성 부작용 제거**: netconvert 결과의 전체 network를 교체하지 않고, 인덱스와 via 연결이 일치하는 단순 합류 3곳의 junction type/request/state만 반영한다. 모든 내부·외부 차로 형상·길이·권한과 연결을 검사한다. 엇갈림 길이 51.07m를 보존했다. 기존 방식의 29.32m 축소를 회귀 테스트가 검출한다.
2. **단순 합류의 과도한 양보 제거**: 목적 차로가 겹치는 합류만 zipper 충돌 관계로 처리한다. 서로 다른 차로로 진입하는 차량까지 모두 기다리게 했던 관계를 제거했다. 교차로 내부 충돌 검사도 켰다.
3. **엇갈림 교착 실측**: 형상 보존+북쪽 수요 조정만 적용한 seed1002에서 05번 승용차가 차로2→3, 14번 버스가 차로3→2를 요청했다. `getLaneChangeStatePretty`가 양쪽 모두 strategic/urgent/overlapping으로 차단됨을 확인했다. 경로 정보 부족이 아니라 상대 차량과 종방향 위치가 겹쳐 안전한 이동 공간이 없는 상황이다. 승용차 위치38.50m, 버스 위치51.07m, 버스 길이12m였다. 근거는 `results/hv_flow_repair_20261113/weave-diagnosis.json`.
4. **협조 시간 변경 실패 기록**: 일반 HV의 lcCooperativeHelpTime 60→5초만 바꿔도 같은 교착이 남았다. 최종 조건에서는 이 변경을 채택하지 않았다.
5. **엇갈림 접근 운용 속도 변경**: 양쪽 접근 및 엇갈림 3개 edge의 속도를 22.22→11.11m/s로 낮췄다. 나머지 형상·권한·연결은 동일하다. 형상 보존+북쪽 분배 조건과 비교해 실패 seed1002가 완주했다. 1시간 신규 seed 6회도 완주했으나 남쪽 출발 대기열이 계속 늘어났다.
6. **남쪽 수요 편중 완화**: 03·04·05번 각600→450, 06번600→1050대/시간. 북쪽 변경과 합쳐도 전체 10,200대/시간은 유지한다. 1시간 시험에서 최대 출발 대기233~270대가3~6대로 줄었다. 이는 실측 수요 복원이 아니라 운영 가능한 진출 비율을 정한 것이다.
7. **비협조 운전자 검증**: 승용차 중2%인 기존 violator vType에 lcCooperative=0, lcCooperativeSpeed=0을 명시했다. 안전 간격 및 SUMO 충돌 회피는 유지한다. 1시간 신규 seed6회와 과거 실패 seed3회 모두 통과했다.
8. **한산한 도로 확인**: 총수요20%에서 불필요하게 교대 차량을 기다리는지 확인했다. 최종 조건 3회 전부 완주, 평균 정지 대기0.001~0.002초. 이 조건에서는 불필요한 지퍼 대기가 관측되지 않았다.
