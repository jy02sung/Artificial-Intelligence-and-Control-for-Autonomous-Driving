# jys3 차로 연결에 따른 실제 분기 통과

기존 v3에서는 16번 차량이 출구 전용 0차로에서 계속 가속해도 지정 경로가 본선이라 SUMO가 차량을 차로 끝에 세웠다. 이 상태에서는 정책이 잘못된 출구로 실제 진입한 순간의 벌점을 경험하기 어렵다. 새 환경은 차량이 실제 점유한 차로로 갈 수 있는 도로를 SUMO 실행 경로에 반영하고, 내비와 보상은 출발 때 지정한 임무를 기준으로 계산한다.

## 작동 방식

분기 접근 중 매 스텝 시작 시 실제 차로를 확인한다. 현재 차로에서 지정된 다음 도로로 이어지면 그 도로를 따른다. 다른 도로로만 연결되면 SUMO 실행 경로를 그쪽으로 변경한다. 차량이 분기를 건너기 전에 적합한 차로로 옮기면 원래 임무 경로로 돌아온다. 양쪽으로 모두 이어지는 공용 차로에서는 내비 경로를 따른다. 실제 연결이 없는 차로에서는 기존 끝 정지 판정이 적용된다. 잘못된 외부 도로에 진입한 스텝에 −5를 지급하고 종료한다. 정상 분기 보상은 +1이고 같은 스텝에 정상 전진분도 합산될 수 있다.

## 확인한 주행

- SUMO 지도 7개 분기에서 지정 다음 도로와 실제 차로의 조합 46개를 확인했다. 13·16번 첫 분기에서는 0·1차로 유지와 통과 직전 차로변경을 별도로 확인했다. 각 테스트는 지정 도로, 실제 도로, 종료 여부, 분기 보상을 검사한다.
- S2 학습 시드 11의 25만 가중치를 고정했다. 고교통 시드군 41110000, 출발 조건 0번, 16개 경로 각 1회의 기존 기록과 같은 주행을 비교했다. 정책 업데이트는 0회다.

|환경|완주|충돌|차로 끝 정지|일반 시간초과|실제 경로 이탈|
|---|---:|---:|---:|---:|---:|
|기존 고정 경로|8|0|7|1|0|
|차로에 따라 분기 통과|7|0|3|1|5|

경로 2·8·13·16은 끝 정지에서 실제 오진입으로, 경로 4는 완주에서 실제 오진입으로 바뀌었다. 16번은 기존 259스텝 끝 정지에서 113스텝 출구 37927508 진입으로 바뀌었다. 13번은 첫 출구를 통과한 뒤 430스텝에 170059994에서 지정된 1063527748 대신 844484876으로 진입했다. 남은 끝 정지 3건은 6·10번의 86198708과 11번의 206426298이었다. 두 도로 모두 0차로에서 이어지는 다음 차로가 없었고, 1~4차로에서만 다음 도로로 진행할 수 있었다. 이 16회는 환경 동작 확인에 사용한 한 학습 시드의 한 출발 조건이다.

## 실행

새 학습·평가 진입점은 `python -m utils.jys3_physical_forks`이다. v3 S2 연장 실험은 기존 환경으로 계속 학습한다. 새 가중치와 평가 기록은 `results/jys3_ppo_comparison/pure_f/physical_forks`에 저장한다.

위 고정 가중치 재생 명령은 다음과 같다.

```powershell
python -m utils.jys3_physical_forks --evaluate --arm S2_dir_col7 --seed 11 --steps 250000 --panel 41110000 --case 0 --checkpoint results/jys3_ppo_comparison/pure_f/reward_simple_v3/stage1/S2_dir_col7_11/policy_250000.pt
```
