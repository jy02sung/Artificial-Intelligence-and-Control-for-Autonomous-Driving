# 사전 안내 / 목적지 차로 보상 독립 비교

사용자가 승인한 두 변경을 각각 기준과 비교한다. 기존 실험 브랜치에서 작업하며 main과 원래 결과는 보존한다.

| 조건 | 관측 | 보상 |
|---|---|---|
| baseline | 기존 경로 안내 | 기존 |
| guidance | 아래 사전 안내 보완 | 기존 |
| route_reward | 기존 경로 안내 | 아래 선택·유지 보상 |

모두 같은63차원 입력(미사용 예약채널0), 동일 초기 가중치/seed11, 각200,000스텝, 기존PPO 파라미터,15,000대/h,16경로,경로안내300m. 정책은 새로 학습한다. 강제 보정·행동 필터·도로·HV·출발조건은 변경하지 않는다.

## 사전 안내

직결 lane link만 역추적하던 방식에 앞으로 같은edge에서 해야 하는 차선변경 비용을 포함한다. 첫 제한 분기까지 남은 거리와 최소 차선변경 수를 이용해 현재 준비 차로를 제시한다. 단일차로 램프처럼 지금 옮길 곳이 없어도 다음 제한 구간의 목표 차로 mask와 그곳까지 차로변경 없이 연결될 경우 필요한 상대 방향을 별도로 전달한다. 현재 안내와 준비 안내의 유효성을 별도 표시하여 계산불가와 방향0을 구분한다.

추가16개 예약 채널: 현재안내 유효성, 준비안내 유효성, 미래분기 존재, 미래거리, 미래목표mask6개, 미래상대방향, 미래직결 도달차로 계산유효성, 최소변경비용, 나머지3개0. 미래mask는0~5차로에 대해 목표1/비목표-1/없는차로0이다. 거리와 비용은 정규화한다. 현재 실선edge의 차선변경은 계획 비용에서도 허용하지 않는다. 이는 정적 경로 안내이며 교통 상황에서 변경 가능한 안전한 틈을 보장하지 않는다. 다른 차량의 미래 경로는 입력하지 않는다.

## 목적지 차로 선택·유지 보상

기존 안내는 그대로 두고, 현재edge의 다음 목적 도로로 연결되는 차로를 목표로 삼는다. 목적지 차로가 제한되는edge에서 남은 거리300m 이내만 평가한다.

- 목표 차로까지 거리(차로 수)의 새 최솟값을 달성하면 줄인 차로당+0.1. 같은 구간에서 왕복해도 재지급하지 않는다.
- 이미 맞는 차로를 떠나면-0.1.
- 맞는 차로에서 실제로 진행한 거리당+0.005, 구간별 최대+0.5. 정지 상태에는 유지 보상0.
- 충돌/도착 종료 보상은 기존값만 적용한다. edge 경계 변화는 같은edge 차로변경으로 계산하지 않는다.

계수는 초기 비교값이며 최적값이라는 의미가 아니다. 시간초과 벌점과 별도정지 벌점은 이번 조건에 함께 넣지 않는다.

## 구현·검증 순서

1. `tests/test_route_following_trials.py`: 단일차로 합류 후 준비, 상류 준비, 연결부재, 정지·왕복 보상 테스트 실패 확인.
2. `env/route_following_trials.py`: 안내 및 보상만 구현. 기존 source 파일 수정 없이 wrapper로 분리.
3. 실제 맵16경로의 안내 schema/연결/부호 점검, 기존관측·보상의 기준 동등성 검증.
4. `utils/run_route_following_trials.py`: 기존 학습 실행기 재사용,32스텝 사전 실행 후3조건 병렬 학습. 초기 가중치와 입력해시 확인 후 고정.
5. 약10만·20만 모델마다 교통16경로×3seed(19101~19103),무교통16경로×1seed 평가. 학습 종료 후 자동으로 평가한다.
6. 완주/충돌/기타 외에 필요한 방향 요청률·동일edge 실제 변경·맞는 차로 유지율·맞는차로 이탈·비연결차로 끝 정지를 기록한다. 스텝률과 사건 횟수를 구별하며 정지 때문에 표본수가 커진 경우를 별도 해석한다.

원시자료는 `results/route_following_trials_20261114/`, 코드·설계·작은 결과표만 GitHub에 올린다. 결과 이전에 개선을 주장하지 않으며 학습seed1개의 탐색 결과로 최종 우열을 확정하지 않는다.
