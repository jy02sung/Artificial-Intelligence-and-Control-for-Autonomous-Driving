# 퇴계원IC 입구 연장 맵: HV 경계조건 검증

## 목적과 고정 조건

`adbd43c`의 입구 연장 맵에서 AV 없이 HV만 검증한다. 이전 본선 중심 15,000대/h 통과 결과가 다른 수요와 차량 구성에도 유지되는지 조사한다. 유한한 36회 실험으로 모든 실패 가능성을 증명하거나 배제하지 않는다.

맵, 16개 경로, 차로 권한, 안전거리, 지퍼 우선권, 속도 설정은 그대로 둔다. 텔레포트는 끄고 교차부 충돌을 검사한다. 충돌 차량 제거는 도착으로 인정하지 않는다. 버스 제어기는 IDM으로 고정한다. 각 조건에 동일 seed 8101·8102·8103, 최대 6개 프로세스를 사용한다. 입력별 총 계획 대수는 15,000대이며 7,200초까지 잔류 차량을 추적한다.

| 조건 | 기준에서 독립적으로 바꾼 항목 |
|---|---|
| reference | 기존 본선 중심 수요, 버스 5%, 승용차 중 비협조 운전자 2% |
| proportional | 과거 10,200대/h의 모든 경로를 비례 확대해 총 15,000대/h |
| north_exits | 북쪽 직진 16번에서 13·14·15번으로 각각 600대/h 이동; 입구별 총량 유지 |
| south_exits | 남쪽 직진 06번에서 03·04·05번으로 각각 600대/h 이동; 입구별 총량 유지 |
| east_exit | 08번에서 07번으로 600대/h 이동; 동쪽 입구 총량 유지 |
| compressed | 같은 15,000대를 60분 대신 45분 동안 투입: 유입 중 20,000대/h |
| bus10 | 버스 비율만 5%→10% |
| violator5 | 승용차 중 비협조 운전자 비율만 2%→5% |
| krauss / idm / eidm / acc | 승용차의 제어기 구성만 각각 한 종류로 변경 |

버스·비협조 비율은 차량 유형 추출 확률이며 유한 표본의 실제 비율은 정확히 같지 않을 수 있다. 제어기 단일화는 제어기별 기존 가감속·tau 등 유형 설정을 함께 사용한다. 같은 seed라도 차량 구성 변화 후 궤적은 달라진다.

## 판정

- 경로별 계획=투입=도착, 충돌·텔레포트·종료 시 잔류·출발 대기 모두 0일 때 완주 통과.
- 완주해도 출발 대기, 최대 정지 차량, 수요 종료 후 배출 시간, 급제동 경고를 별도로 확인한다. 뒤늦게 투입해서 모두 완주한 것을 원활한 15,000대/h 처리로 해석하지 않는다.
- 시간초과는 출발 미투입과 도로 위 잔류를 나눈다. 정지 표본은 잘못된 차로 끝, 앞차 대기, 연결부 앞 대기, 기타로 분류한다. 이는 관측 기반 진단이지 단독 인과 증명은 아니다.
- 충돌 카운트는 SUMO가 보고한 충돌 차량 이벤트 수이며 고유 사고 건수나 AV 충돌률이 아니다.

## 실패 원인 분리용 후속 검증

`python -X utf8 -m utils.hv_entryprep_stress_followup`

### 발견한 취약점과 증거

1. **남쪽 램프 수요 집중**: 03·04·05번을 각각 450→1,050대/h로 늘리고 06번을 줄여 남쪽 입구 총량은 유지했는데, 3회 모두 7,200초까지 끝나지 않았다. 합계 출발 대기 99대와 도로 위 잔류 111대. 잔류 111대 전부 속도 0.5m/s 이상, 대기시간 0초였으므로 종료 순간의 영구 정지 교착 증거는 없다. 8101에서 03~05번 도착 차량의 평균 출발 지연은 각각 약 1,818·1,824·1,816초였다.
2. **북쪽 진출 쏠림**: 13·14·15번 각각 200→800대/h, 16번 감소로 입구 총량 유지. 완주는 했으나 해당 진출 경로의 평균 출발 지연은 8101에서 약 1,449~1,454초. 첫 분기 거리를 확보해도 출발 차로·진출 수요의 집중은 별도 문제다.
3. **동쪽 합류 전 대기열**: 비례 수요 확대의 8101에서 `544295537`의 앞차 대기 정지 표본이 35,985 차량·초로 집중됐다. 01·02번 평균 출발 지연 약 552~557초, 03~05번 약 482~487초. `east_exit`에서는 07번 평균 출발 지연 485~526초. 이는 출구별 수요 분배에 민감하다는 증거이며 연결 오류로 단정할 근거는 아니다.
4. **집중 유입**: 같은 총 15,000대를 45분에 투입하면 유입 중 20,000대/h가 된다. 완주하더라도 최대 2,082대가 출발 대기하므로 원활한 처리로 분류하지 않는다.
5. **급제동**: ACC 승용차 구성은 45,000대 평가에서 급제동 경고 507회, 기준 혼합은 27회. 특히 `206426298` 및 `206426298#1`에 집중한다. 이 경고만으로 충돌 위험의 원인을 단정할 수는 없지만 추후 차로 변경 직전 앞뒤 간격과 가속도 추적이 필요한 구간이다. EIDM은 경고 3회지만 출발 지연이 기준보다 크므로 단일 지표만으로 최적 제어기를 고르지 않는다.

[실행별 CSV](ic-hv-stress-20261113.csv). 정지 분류와 근거 차량·시각·차로·앞차 정보는 로컬 `analysis.json` 및 각 `complete.json`에 있다. 도로와 기본 트래픽 설정은 변경하지 않았다.

## 후속 6회 결과와 결론

- **south_drain**: 8101/8102/8103에서 각각 7,331.6 / 7,398.4 / 7,392.2초에 15,000대 전부 완주. 7,200초 미만의 차량별 도착 시각을 최초 실행의 tripinfo와 대조해 완전히 동일함을 확인했다. 원래 7,200초 제한의 실패 3회는 그대로 남긴다. 종료 시 움직이던 차량과 최종 배출 결과로 볼 때 이번 실패는 영구 교착이 아니라 출발 지연 누적이다.
- **free_departure**: 3회 모두 15,000대 완주, 종료 3,696.0 / 4,057.4 / 3,692.8초. 충돌·텔레포트·잔류·출발 대기 0. 이 맵과 수요에서 출발 `best`가 아니면 반드시 실패한다는 가설은 지지되지 않았다. 다만 8102는 지연이 커졌다.
- 전체 **42회·계획 630,000대** 실행에서 충돌 차량 이벤트와 텔레포트는 0. 최초 제한시간 내 완주 실패 3회, 후속 시간 연장 재현은 모두 완주. 반복 실행을 합산한 규모이며 고유 교통 장면 630,000개라는 의미는 아니다.

### 다음 개선 우선순위

1. **진입 지연을 도로 정체와 분리**: 03~05·13~15의 출발 차로/출발 속도/유입 간격과 진출 수요를 진단한다. 현재 `departSpeed=max`, `departLane=best`가 요구하는 안전한 삽입 간격도 후보 원인이다. 용량 부족과 SUMO 삽입 조건 영향은 아직 분리하지 않았다. 실제 도로 위 고정 교착으로 단정하지 않는다.
2. **동쪽 01·02·07·08 합류부**: 1차로 진입 후 짧은 공용 차로 준비 구간과 동쪽 접근 대기열을 집중 추적한다. 인위적으로 수요를 낮춰 통과시킨 결과와 원래 수요의 개선을 구별한다.
3. **급제동 위치**: 남행 `206426298` 계열과 동쪽 `544295537`에서 차로 변경 직전 간격, 앞차 감속, 차량 유형을 기록해 원인을 분리한다. 안전거리 축소로 해결하지 않는다.
4. **운영 범위 명시**: 현 기준 혼합 트래픽은 통과했지만 동일 총량의 모든 수요 분배를 원활히 처리하지는 못한다. 처리 가능한 유입/진출 조합을 정한 뒤 AV 학습 재개를 판단한다.
