상태: **완료**. 안전 게이트·행동 필터 없음(정책 단독 주행). 실행 코드 `utils/pmh_jys3_expert_v3.py`, `utils/pmh_jys3_dagger_fix.py`. 실행 커밋 `3224b9e`(pmh). 이전 단계는 [6라운드까지](../pmh-jys3-dagger-multi/README.md)에 있다.

## 조건

- **시작 가중치**: `models/pmh/jys3_dagger6_crash.pt`. 6라운드 모델로, 최종 256회에서 완주 239, 충돌 11, 정지 6이었다.
- **이전 데이터**: BC v2 시범, jys3 1라운드, crash 체인 2~6라운드를 모두 이어서 쓴다.
- **비교 조건 두 가지** (7~10라운드, 4라운드씩)

| 조건 | 내용 |
|---|---|
| `control` | 6라운드 방식을 그대로 이어서 학습한다(v2 전문가 라벨, 충돌 직전 3초 추가 추출). |
| `fixed` | 아래 세 가지 수정을 적용한다. |

- **`fixed`의 수정 사항**
  1. **전문가 v3 라벨**(정지 원인)
     - 적용 조건: 차로 끝 15m 이내, 3m/s 미만, 현재 차로로는 경로 진행이 불가, 실선이 아님.
     - 이 조건에서만 틈 기준을 완화한다. 앞 간격 > 2.5m, 뒤 간격 > 2m + 1초 × 뒤차 접근 속도이고 겹침이 없으면 차로를 바꾼다.
     - 그 밖의 상태에서는 v2와 같다. 이전 데이터 전체를 오프라인으로 다시 라벨링했고, 차로 명령이 바뀐 상태는 128개였다.
  2. **불일치 상태 추가 학습**(충돌 원인). 매 에폭 현재 모델의 차로 명령이 라벨과 다른 상태를 다시 찾아, 배치마다 64개씩 더 뽑는다.
  3. **엇갈림 경로 추가 수집**. 라운드마다 3·4·5·13·14·15번 경로를 24회 더 주행해 데이터를 모은다.
- 지도학습 설정(12 에폭, Adam 2e-4, 에폭 선택)과 평가 세트는 이전과 같다. 학습 seed는 11이다.

### 전문가 v3 사전 검증 (`expert_v3_checks.json`)

- 전문가가 직접 운전한 256회(30010000대): v2 255 완주·시간초과 1, v3 255 완주·시간초과 1로 같다.
- 6라운드 학생이 정지한 6건에서 정지 2초 뒤 전문가에게 운전을 넘겼다. v2는 1건, v3는 3건을 빠져나왔다.
- 처음 만든 판은 틈이 없을 때 조금씩 전진했다. 그 판은 전문가 단독 256회에서 정지가 5건이었다. 정지 판정은 차로 끝 5m 이내에서 시작되는데 v2는 약 14m 앞에서 기다리기 때문이다. 그래서 전진 규칙은 뺐다.

## 해석

- 라운드를 늘리는 것만으로도(control) 충돌이 11에서 3으로 크게 줄었다. 대신 정지가 6에서 11로 늘었다. 충돌하던 상황이 정지로 바뀐 것이다.
- 수정을 적용한 fixed는 control보다 완주가 3건 많고 정지가 2건 적다. 7·8번의 정지는 사라졌다.
- 다만 학습 seed가 하나이고 차이가 작아서, 세 수정 중 어느 것이 효과를 냈는지는 이 실험만으로 구분할 수 없다.
- 남은 실패의 대부분(9/11)은 엇갈림 구간 경로(13·14번)와 5번의 차로 끝 정지다. 전문가 v3도 정지 6건 중 3건(14번, 5번, 7번 각 1건)은 빠져나오지 못했다. 엇갈림 구간 끝에서 정지한 상태로 끼어드는 문제는 전문가 규칙으로도 아직 풀리지 않았다.
