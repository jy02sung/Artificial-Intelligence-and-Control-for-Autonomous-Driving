# HV 높은 트래픽: 15,000대/시간

## 목표와 고정 조건

사용자 요청에 따라 높은 트래픽을 전체 진입부 합계 **15,000대/시간**으로 정의한다. AV는 계속 중단한다. 실측 재현이 아닌 운영 검증 수요다.

- 기준: `scenarios/hv_stable`의 10,200대/h를 경로별 비율 그대로 15,000대/h로 증가. 합계 보존 정수 배분.
- 총16경로, 버스5%, 승용차 중 비협조2%, 4개 추종모델, 합류 우선권·40km/h 운용 구간 유지.
- 맵 형상/차로 수/연결/차선변경 권한/안전거리 불변. 교차로 충돌 검사 활성, teleport 비활성.
- 1시간에 **number=15,000대**를 생성. 실제 투입량, 도착량, 외부 대기, 내부 정지, 충돌과 teleport를 각각 확인.
- 통과 기준: 모든 계획 차량 투입·도착, 충돌/teleport/최종 대기/잔류 0. 1시간 유입 후 최대1시간 추가 배출. 최종 도착률뿐 아니라 진입 지연과 배출 완료 시각도 공개.
- 미완료가 있으면 원인부터 확인하는 systematic-debugging 절차 적용. 결과를 맞추기 위해 충돌 제거를 성공 도착으로 세거나 미투입을 분모에서 제외하지 않는다.

## 단계별 실험

1. **대조군**: 위 비율로 총량만 증가, 출발 차로 best/출발 속도 max.
2. **출발 속도 단독 변경**: 경로별 수요와 모든 다른 조건을 고정하고 출발 속도만 10m/s로 변경. 높은 출발 속도 요구로 진입이 지연되는지 비교.
3. 효과가 확인된 설정을 다른 seed 및 지속 유입으로 검증 후 별도 시나리오로 배포. 이전 기준과 실측 시험은 보존.

첫 비교 seed7101/7102/7103, 최대6프로세스 병렬. 입력/코드 SHA256과 기준커밋은 각 manifest에 기록.
실행: `python -X utf8 -m utils.hv_high_traffic --modes baseline speed10`
로컬 결과: `results/hv_high15000_v1/`

## 첫 비교 결과와 후속 가설

기준3회와 전구간 출발속도10m/s3회 모두 전량 도착·충돌/teleport0을 달성했다. 그러나 기준은 평균 진입 대기145–155초, 마지막 도착4892–5003초였다. 모든 출발속도를 낮추면 평균대기는138–147초이지만 마지막 도착5386–5459초로 악화됐다. 따라서 전구간 속도 변경은 채택하지 않는다.

03–05번만 출발속도10m/s로 바꾸는 조건과, 경로별 수요를 고정하고 출발차로만free로 바꾸는 조건을 각각 독립 비교한다. 출발 후 HV의 차선변경은 SUMO의 안전/경로 판단으로 처리하며 외부 강제 차선변경은 없다.

## 운영 수요 선택

경로별 비율을 모두 그대로 1.47배 늘리면 01/07번의 같은1차로 출구, 03–05번의 진출 경로 등에 수요가 집중됐다. 제어기의 안전거리·충돌 검사를 약화하지 않고 출발 설정을 비교했지만 한 지점이 좋아지면 다른 진입 대기가 악화됐다.

따라서 최종 후보는 **기존 안정화10,200대/h의 램프·일반도로 수요를 유지하고, 본선 직진06번에3,600대/h,16번에1,200대/h를 추가한15,000대/h**다. 이는 HV 제어기 자체의 성능 향상을 증명한 것이 아니라 **고교통 운영 수요를 새로 정의한 것**이다. 모든 진입부의 양을 유지한 중간 배분 실험과도 다르며, 단순 균등 증량이 아니다. 기존 지퍼우선권/운용속도/비협조설정은 그대로다.

- 남쪽 본선 입력6,000대/h, 북쪽 본선4,200대/h, 나머지4,800대/h.
- 16경로 모두 유지. 06번4,650대/h,16번3,600대/h이며 나머지 경로는 기존 안정화 수요 그대로다.
- 총량을15,000보다 줄이거나 생성 못한 차량을 완주율 분모에서 빼지 않았다.
- 앞선 실측 범위 시험은 별도 보존. 이번 수요를 실제 관측 OD라고 발표하지 않는다.

후보3회(seed7101–7103): 전량완주,충돌/teleport/잔류/미투입0. 평균진입지연0.196–0.224초,최대미투입대기4–5대,마지막도착3685.0–3720.2초.
검증 확대: 새seed7201–7203에서1시간,seed7301–7303에서2시간연속유입(각30,000대). 후보 비교에 사용하지 않은seed다.

### 시험 장치 오류

`free-7102`는 교통 문제가 아니라 Windows의일시적파일잠금으로progress.json교체가거부되어중단했다. 이것을 교통실패/성공으로 집계하지 않는다. 나머지free두회는7,200초에잔류105대,미투입3,647–3,655대로실패했다. free출발방식은채택하지않는다. 상태저장에PermissionError제한재시도를추가하고일시적/지속적잠금단위테스트를통과했다(99190ae). 기존부분로그는보존한다.
