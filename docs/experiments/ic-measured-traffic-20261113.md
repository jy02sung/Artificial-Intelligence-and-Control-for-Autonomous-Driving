## 자료와 해석

- 원출처: [도로교통량정보제공시스템](https://www.road.re.kr/itms/itms_01.asp), [교통량 검색서비스](https://www.road.re.kr/itms/itms_22.asp?main_no=16&sub_no=1)의 **시간대별 차종별 교통량(수시)**.
- 조회 연도 2025, 실제 조사일 **2025-10-16**. 2026-11-13 조회. 연평균 시간대별 수요나 실시간 교통량이 아니다.
- 지점 10010: 구리IC–퇴계원IC, 양방향 합계 **193,127대/조사일**.
- 지점 10031: 퇴계원IC–별내IC, 양방향 합계 **120,134대/조사일**.
- [10010 원자료](https://www.road.re.kr/itms/itms_22_data.asp?data=3&year=2025&spot=10010), [10031 원자료](https://www.road.re.kr/itms/itms_22_data.asp?data=3&year=2025&spot=10031).
- 각 지점 48행(24시간 × 2방향), 총 96행. 12개 차종 합계와 행 total, 일 합계 일치 확인.
- [전체 원자료 정리 CSV](road-hourly-20251016.csv)에 차종 12개, 방향 코드, 원본 시간 표기, 조사일과 다운로드 XML SHA256을 기록했다. 원본 XML은 로컬 `results/road_research_20261113`에 보존한다.

**미확정 항목:** 방향 코드 1/2의 실제 진행 방향, 시간 표기가 10010은 0–23이고 10031은 1–24인 이유. 이를 임의로 정규화하거나 특정 방향이라고 단정하지 않았다. 아래 숫자는 원본 시간 라벨 그대로다. 두 조사 지점은 IC 양옆을 통과하는 교통량이며, IC 램프별 유입·진출량이 아니다. 두 지점 일 교통량을 합쳐 IC 이용 차량 수라고 하면 중복 집계가 된다.

## 시험 설계: 실측 범위 기반 민감도 시험

실제 동시간대 교통을 정확히 재현한 시험은 아니다. 방향·시간 기준을 확정하기 전에도 도로가 견디는 부하를 확인하기 위해, 넓은 시간 라벨 범위에서 **두 방향을 포함한 최솟값/최댓값**을 뽑았다. 서로 다른 시각·방향의 극값 조합이므로 실제 동시에 관측된 유량 조합으로 해석하지 않는다.

- 새벽: 원본 라벨 2, 3. 출근: 7, 8, 9. 퇴근: 16, 17, 18.
- 남쪽 본선 진입(경로 03–06): 10010의 해당 범위 유량을 대입. 북쪽 본선 진입(13–16): 10031 대입. 조사 단면을 시뮬레이터 경계로 옮긴 대용 입력이며, 동일 단면이라고 검증한 것은 아니다.
- **가정 유지:** 램프별 분기 비율은 안정화 시나리오 비율 유지. 나머지 진입부 합계 4,800대/시간 유지. 실측 OD·금강로 수요는 확보하지 못했다.
- 차종은 기존 승용차+버스 5%, 승용차 중 위반 운전자 2%, 4개 기본 제어기 구성 유지. 실측에는 화물차도 포함되므로 **이번에는 차량 수만 반영**하고 실측 차종 구성은 재현하지 않았다.
- 맵, 우선권, 지퍼 합류, 안전 설정, 속도, 출발 설정은 `scenarios/hv_stable` 그대로. AV 없음. 차량 삭제로 정체 해소하는 teleport 비활성화. 충돌은 별도 실패로 기록.
- 각 조건 1시간 유입, 최대 2시간까지 배출 확인. seed 6101/6102/6103, 6조건 × 3회 = 18회, 최대 6프로세스 병렬.
- 판단: 계획 차량 모두 투입·도착, 충돌 0, teleport 0, 미투입/잔류 0. 추가로 진입 대기 및 통행 중 정지, 실패 위치를 기록한다. 최종 도착률만으로 정체가 없다고 주장하지 않는다.
- 관측 교통량은 통과량이다. 정체 때문에 통과하지 못한 잠재 수요까지 나타내지는 않는다.

실행: `python -X utf8 -m utils.hv_measured_traffic`
로컬 실행/원시 로그: `results/hv_measured_20261113_exact` (git 제외).
각 입력 manifest에 기준 커밋, 파일/코드 해시, 가정, 총 유량을 기록한다. 기존 실험 결과와 정책을 덮어쓰지 않는다.

### 실패 원인 구분

- 높은 출근·퇴근 조건의 미완료는 **03/04/05번 경로**에 집중됐다. 해당 조건의 미투입 차량도 모두 이 세 경로다. 모든 다른 경로는 계획 차량을 전부 처리했다.
- 높은 출근 조건의 이 세 경로 평균 진입 지연은 **1,971–2,043초**, 높은 퇴근 조건은 **2,133–2,147초**다. 반면 도착 차량의 주행 중 평균 정지 시간은 **0.04–0.23초**다.
- 높은 출근·퇴근 조건 종료 시 도로 안에 남은 차량은 **전부 이동 중(speed > 0.5m/s), 현재 대기시간 0초**였다. 이번 미완료를 잘못된 차로 끝에 정지하거나 합류에서 영구 교착한 것으로 분류할 근거는 없다.
- 이 결과가 직접 보여주는 문제는 **경계 진입 처리량보다 해당 경로의 예정 출발량이 큰 것**이다. `departLane=best`, `departSpeed=max`는 기존 설정 그대로다. 이 출발 설정이 얼마나 영향을 주는지는 독립 비교 전이므로 원인으로 확정하지 않는다.
- 현재 남쪽 유량의 **56.25%**를 03/04/05 세 진출 경로에 배분한다(각18.75%). 이 비율은 실측값이 아니다. 본선 실측 통과량을 늘리면서 이 비율도 고정했으므로 램프 수요가 함께 크게 증가했다. 따라서 **실제 퇴계원IC에서 같은 정체가 발생한다는 결론도, 지퍼 합류가 실패했다는 결론도 낼 수 없다.**
- 총 충돌 0, teleport 0. 급제동 경고는 있으므로 모든 주행이 부드럽거나 실도로 수준으로 검증됐다고 주장하지 않는다.

### 다음 검증에 필요한 것

1. 조사기관의 방향 코드와 0–23/1–24 시간 기준을 확인하여 두 지점의 동일 시간대 **유입 방향**을 정확히 선택한다.
2. 퇴계원IC 램프 진출입량 및 금강로 방향별 수요/회전비를 추가 확보한다. 확보되지 않으면 비율을 복수 가정한 민감도 시험으로만 발표한다.
3. 수요와 도로를 고정하고 출발 차로/출발 속도만 바꿔 경계 투입 제한을 독립 검증한다. 유량을 낮춰 놓고 실측 수요를 통과했다고 처리하지 않는다.
4. 실측 차종(화물차 포함)까지 재현할지 수업 범위에 맞춰 별도로 정한다. 현재 결과는 기존 승용차·버스 혼합의 유량 부하 시험이다.

재현 코드: `18a3784`(수집/설계), `cfacd94`(정확한 계획 차량 수). 실행 당시 manifest의 부모 커밋 외에 각 파일/스크립트 해시를 함께 기록했으므로 수량 수정 후 코드를 식별할 수 있다. 맵 SHA256은 여섯 조건 모두 `scenarios/hv_stable/network.net.xml`과 동일함을 확인했다. 대용 입력 실험 결과이며 AV 학습 재개 조건으로 자동 채택하지 않는다.
