# 고정 후보 검증 계획

## 목적과 고정 조건
기존 교통 모델과 두 후보를 재학습 없이 비교한다. 모델·관측·보상·맵·HV 조건은 후보 선정 당시 그대로 유지한다. 강제 보정은 사용하지 않는다. 체크포인트 및 입력 파일 SHA-256과 코드 커밋은 results/traffic_safety_validation_20261115/manifest.json에 기록한다.

## 1단계: 신규 seed 검증 — 실행 대상
- 신규 교통 seed 49101~49120 × 16경로 × 3정책 = 960회.
- 같은 seed·경로·교통 입력으로 대응 비교. 3개 CPU 프로세스, 각 PyTorch 1스레드.
- 이전 평가와 동일한 900초 예열, AV 평가 최대10800초. 제한시간을 바꿔 성능을 높이지 않는다.
- 완주, 충돌, 시간 초과, 잘못된 출구, 삽입 실패를 별도 기록한다. 시간 초과를 충돌로 합산하지 않는다.
- 충돌·시간 초과 직전 관측/행동/속도와 차로 선택·위험 시 감속 지표를 저장한다.
- 경로별 결과를 검토해 전체 평균이 특정 경로 실패를 가리는지 확인한다.
- 3개 정책의 실제 주행 스모크 검증 후 본 검증을 시작한다. 스모크 결과는 정식 집계와 분리한다.

## 판정과 후속 순서
1. 길찾기 목표: 완주+충돌 비율이 100%에 가까운지, 기타 실패의 경로·원인을 확인한다. 이는 안전 목표 달성과 다르다.
2. 최종 안전 목표: 충돌률5% 미만과 충분한 완주율을 함께 확인한다. 신뢰구간과 경로별 표본 수도 보고한다. seed 내 경로 결과의 상관을 고려하고 단순 표본 비율만으로 확정하지 않는다.
3. 후보가 유효하면 낮은 교통량과 무교통 회귀 평가, 별도 학습seed22·33 재현으로 확장한다. 현재 실행 범위는 1단계이며 아직 재학습을 시작하지 않는다.
4. 이번 seed는 개발 검증용이다. 결과를 보고 설정을 고르면 최종 보고용 미사용 seed 평가를 별도로 남긴다.

원본과 실패 기록은 보존한다. 모델과 원시 결과는 로컬에, 요약과 실행 코드는 작업 브랜치에 기록한다.
