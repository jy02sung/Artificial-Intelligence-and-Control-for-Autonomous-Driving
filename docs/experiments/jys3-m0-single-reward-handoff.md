# 조원용 실험 · 순수 PPO 보상 하나씩 바꾸기

우리 PC에서 진행하는 M0~M5-FT와 독립적으로, 단순 보상 M0의 **완주·분기·충돌 중 어느 한 항이 같은 주행의 결과를 바꾸는지** 검증한다. 조원은 아래 공통 프롬프트를 복사하고 첫 줄에 자신의 담당을 붙이면 된다. 한 사람이 두 조건을 맡으면 조건을 하나씩 실행한다. 서로 다른 PC에서는 동시에 시작할 수 있다.

| 담당 | 첫 줄 | M0에서 바꿀 유일한 값 | 가장 먼저 볼 지표 | 전환표에서 확인할 것 |
|---|---|---|---|---|
| 1순위 · 도착 | `담당 조건은 arrival이다.` | 지정 경로 완주 +5 → +10 | 완주율 | 기존 끝 정지·일반 시간초과 → 완주, 기존 완주 → 실패 |
| 1순위 · 분기 | `담당 조건은 fork이다.` | 올바른 분기 최초 통과 +1 → +2.5 | 실제 이탈률, 차로변경 필요 출발 /208 완주율 | 기존 이탈 → 완주 또는 첫 분기 이후 다른 실패 |
| 추가 담당 · 충돌 | `담당 조건은 collision이다.` | 실제 충돌 −5 → −12 | 충돌률과 완주율 | 기존 충돌 → 완주·이탈·끝 정지·일반 시간초과 각각 몇 건인가 |

종료 전환표의 이탈→충돌은 두 정책에서 종료 사유가 바뀌었다는 뜻이다. 사고 위치와 분기 통과 시점은 별도의 주행 기록으로 확인한 사례에만 표시한다.

## 복사할 공통 프롬프트

```text
팀 저장소 https://github.com/jy02sung/Artificial-Intelligence-and-Control-for-Autonomous-Driving 의 jys3 브랜치에서 위에 지정한 보상 조건 하나를 구현 코드로 실행하고, 같은 시드의 M0와 직접 비교해줘. 실행기는 utils/jys3_m0_single_reward.py, 기준 구현은 utils/jys3_ppo_clean_ladder.py의 M0다. 내 PC 작업 폴더에서 원본 jys3를 기준으로 시작하고 결과는 담당 조건 전용 폴더에 저장해줘.

1. 시작 전 python -m utils.jys3_m0_single_reward 담당조건 --check 를 실행해 세 시드의 초기 정책 SHA 일치와 보상표를 확인해줘. M0 보상은 경로 전진 누적 +2, 올바른 분기 +1, 완주 +5, 충돌 −5, 경로 이탈 −5, 끝 정지·일반 시간초과 −5다. 담당 항목 하나만 바꿔. 세 후보는 M0에서 각각 독립 출발한다.

2. M0와 동일한 수정 분기, 고가 교차 20쌍 시야 보정, 고교통 15,000대/시, 16경로, 50차원 관측(meta.signs), 안전게이트 OFF, 공유 Critic의 256×256 ReLU 정책을 써. 순수 PPO 무작위 초기화다. γ=0.99, GAE λ=0.95, lr=1e-4, 롤아웃 2,048, 10에포크, 미니배치 64, 차로 엔트로피 계수 0.002, 차로 유지 초기 편향 1.0을 고정한다. 원래 M0의 차로 끝 정지·일반 시간초과는 유지한다. 앞빈 저속 셰이핑과 10초 조기 종료는 꺼진 상태다.

3. python -m utils.jys3_m0_single_reward 담당조건 --workers 4 로 시드 11·22·33을 각각 25만 스텝 학습해줘. 중단 시 같은 명령으로 재개해. 5만 단위로 95380000 패널 128회에서 결정론적으로 평가해. 각 시드에서 완주 최대 → 충돌 최소 → 변경 필요 출발 완주 최대 → 이른 스텝 순으로 대표 모델 하나를 고른다. 각 조건은 자체 선정 모델을 사용하고, 같은 스텝의 중간 결과도 함께 보여줘.

4. 선정 모델을 고교통 576회(81260100 계열 64회, 91000000·104320000 계열 각 256회)에서 검증해. 같은 시드 M0와 경로·출발 차로·교통 시드·출발 관측 해시를 1:1 대조해. M0의 결과는 우리 팀이 공유한다. M0 파일 도착 전에도 후보의 학습과 평가를 모두 마치고 결과를 저장해. M0 자료 수신 후 python -m utils.jys3_m0_single_reward 담당조건 --summarize 로 재학습 없이 전환표를 생성해.

5. 보고서 첫 표에는 M0와 후보의 시드별 및 3시드 평균 완주·충돌·이탈·끝 정지·일반 시간초과 건수와 비율을 붙여 써. 건수의 분모는 시드마다 576회, 변경 필요 출발 완주의 분모는 두 256회 패널에 속한 208회다. 시드별 차이와 3시드 평균 차이를 %p로 쓰고, 기존 완주 유지·상실·새 완주 및 5×5 종료 전환표를 보여줘. 담당 가설과 반대되는 결과도 실제 수치대로 기록해.

6. 최종 공유물은 results/jys3_m0_single_reward/담당조건/ 아래의 protocol.json, comparison.json, report.md와 평가 JSON이다. 팀원이 재검산할 수 있도록 선택한 체크포인트 스텝과 코드 커밋을 함께 적어줘. 결론은 ‘보상 X를 A에서 B로 바꾸자 576회에서 어떤 종료가 어떤 종료로 몇 건 바뀌었다’ 순서로 요약해.
```

## 실행과 기준선 자료

| 항목 | 위치 |
|---|---|
| 실행기 | [jys3_m0_single_reward.py](../../utils/jys3_m0_single_reward.py) |
| M0 원본 및 초기 가중치 해시 | [기준 학습 코드](../../utils/jys3_ppo_clean_ladder.py) · [실험 설정](../../results/jys3_ppo_clean_ladder/protocol.json) |
| M0 기준선 원자료 | `results/jys3_ppo_clean_ladder/M0_s11/`, `M0_s22/`, `M0_s33/` 안의 5개 `eval_*_screen.json`과 선정 스텝의 `hold64/designated/additional` JSON 3개씩 |
| 별도 전달받은 기준선 | `--summarize --baseline-root 경로`. 해당 경로 바로 아래에 위 3개 M0 폴더를 둔다. |

프로젝트 루트에서 실행한다. 팀 실행 환경은 Python 3.10, PyTorch 2.14.0, NumPy 2.2.6, libsumo·TraCI·sumolib 1.27.1이다. 조건당 신규 학습은 75만 스텝, 선정 평가는 1,920회, 최종 평가는 1,728회다. 같은 PC에서 작업을 나누면 전체 워커의 합을 최대 4개로 맞춘다.
