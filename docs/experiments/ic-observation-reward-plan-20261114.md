# AV 관측·보상 독립 비교 설계 — 1차 진단 반영

상태: **M1~M8 1차 진단 완료. 관측 오류 확인으로 후속 학습은 보류. 공통 검출기 수정·검증 후 학습 비교 설정을 확정한다.**

기준: main `b10794c`, 작업 브랜치 `codex/av-observation-reward-20261114`.

개정: 사용자 승인 후 AV24회, HV 지퍼 ON/OFF4조건, 16경로 정적 검사를 수행했다. [진단 결과](ic-meeting-diagnosis-20261114.md)에 확인 사실과 미확정 항목을 구분했다. 진단용 변경을 운영 맵·정책에 반영하지 않았으며 학습은 시작하지 않았다.

추가 전제도 검사했다. 충돌 직전 문맥3개에서 앞차 거리·상대속도를 바꾼84개 입력 모두 감속하지 않았고, 현재 제한속도를 바꾼12개 입력에서도 가속 명령을 유지했다. 차선 변경 시점 통제8회에서는7회가 다시 충돌했다. 이는 **무교통 정책에 정보나 출발 보호만 덧붙여서는 충분하지 않다**는 제한된 진단 근거다. 합성 입력과 행동 개입 시험을 정상 정책의 성공률에 합산하지 않는다.

추가 후보는 `합류 전 연결도로 접근차 관측`과 `다음 낮은 제한속도+거리`다. 차선 변경1초 설정은 재변경 금지시간이 아니라는 점도 확인했으나, 행동 주기 변경은 이번 관측/보상 비교에 섞지 않고 별도 검토한다.

## 목적과 현재 증거

HV 환경을 고정하고 AV가 주변 차량을 인식해 안전하게 차로를 선택하고 감속하도록 관측·보상을 검증한다. 학습률·감마·탐험계수·모델 종류를 이번 비교 변수로 쓰지 않는다.

직전 경로 안내 정책(seed22,600064스텝)은 기본15,000대/시간에서1/16완주·15/16충돌, 높은 진출 수요에서2/16완주·14/16충돌이었다. 이는 **무교통 학습 정책의 트래픽 전이 평가**이며, 같은 환경에서 충분히 학습한 기준 모델이 실패했다는 증거는 아니다. 새로운 모든 조건에는 똑같은 트래픽 학습 기회를 준다.

코드에서 확인한 사항:

- 해당 정책 manifest의 `lane_change_safety.enabled=false`. speedMode0, laneChangeMode0으로 자동 안전제동·자율 차선변경도 꺼져 있다. 이번 주 실험에서는 이 조건을 몰래 켜지 않는다.
- `_neighbor()`의 음수 gap→None 처리는 **실제 충돌 직전7개 사례에서 확인된 관측 오류**다. 음수 gap만으로 이미 차체 충돌했다고 판정하지는 않는다. 별도3개 추돌에서는 앞차가 정상 관측되어 이 오류가 모든 충돌의 원인은 아니다.
- 관측에는 앞뒤 거리와 상대속도가 이미 있다. 같은 정보를 추가하는 것과 오류를 수정하는 것을 구분한다.
- 기본 보상은 속도+0.1×속도/기준속도,6m이내−0.1,막힘−0.05,충돌−5,도착+2,차선변경 벌점0이다. 안전한 추종·정체 대기까지 막힘으로 벌주는지 점검한다.

기존 무교통 정책은 진단 재현용이다. 새 인과 비교는 **동일 초기화에서 새로 학습**한다. 전체 조건에 같은 입력 크기(기존47+예약16=63)를 사용하고 미사용 추가 채널은0으로 둔다. 같은 seed의 모든 조건은 동일 초기 가중치·난수 일정·예산에서 시작한다. 입력 확장이 학습에 미치는 영향까지 기준 조건이 통제한다. 기존47차원 체크포인트에63차원 관측을 바로 넣지 않는다.

63차원은 아래 1차 관측A/B 비교에만 적용한다. 회의 후속 관측에 더 많은 채널이 필요하면 해당 비교군 전체를 같은 크기로 다시 초기화하고 새 기준 모델을 포함한다. 네트워크 크기가 다른 실험의 수치 차이를 관측 정보 하나의 효과로 주장하지 않는다.

### 비교를 해석할 때의 필수 구분

- 현재 코드의 `RouteNavigation` 기본 안내 범위는300m이고, ‘100m’는 별도 준비 보상의 판정 기준이다. 최근 기준 평가에는 그 준비 보상을 켜지 않았다. ‘100m 안내가 짧아서 실패했다’고 미리 결론내리지 않는다.
- HV 네트워크의 지퍼 junction과 AV의 지퍼 관측/보상 코드는 별개다. 최근 평가 경로에서는 `ic.ZIP=()`로 기존 지퍼 사건 목록을 비웠다. 따라서 현재 AV가 ‘지퍼 보상을 받으려고 기다렸다’는 설명부터 해서는 안 된다. 실제 이벤트 연결·발생 횟수를 검사해야 한다.
- M4·M5·M7의 HV/맵/교통량 변경은 **원인 구분용 별도 시험**이다. 관측·보상 학습 표의 고정 환경을 대체하지 않는다. 수요를 낮춘 결과를 기본15,000대 성능처럼 보고하지 않는다.
- 동일 seed도 AV 개입 이후의 HV 궤적까지 동일하게 만들지는 않는다. 최초 상태 일치, 분기 이후 교통 변화, 상대차 ID를 기록한다. 스냅샷 비교가 불가능하면 인과 확정 대신 반복 재현 근거라고 표시한다.
- 합류 상대의 실제 미래 route는 오프라인 정답 라벨 검증에만 쓴다. 정책 입력에는 자기 내비게이션과 현재 감지 가능한 위치·속도·방향지시등만 사용한다. 깜빡이 관측의 사용 가능 여부·가시성·지연 가정은 구현 전에 명시한다.
- 무조건 교대는 비효율 여부를 확인할 진단 대조군이다. 이를 최종 정책으로 채택한다는 뜻이 아니다. 어떤 경우에도 옆 차를 강제로 정지시키거나 AV 차로를 강제 보정하지 않는다.

### 추가 후보의 수치와 실행 승인

회의 후속 비교의 관측 채널, 과속/준비/지퍼 보상 함수·계수, 저밀도 수준, 혼잡 조건(속도·대기열·접근 거리), 복원할 HV 우선권은 아직 **확정 전**이다. M1~M8 진단 결과를 근거로 실행표에 수치·코드·입력 해시를 채워 검토받은 뒤 실행한다. ‘적당히 혼잡’ 같은 가변 기준으로 실험 중 판정하거나 통과 결과에 맞춰 바꾸지 않는다. 진단 항목은 모두 확인하되 근거가 없는 보상을 의무적으로 추가하지는 않는다.

## 0단계: 학습 전 관측·명령·보상 검사

전체16경로의 정적 경로·사건 목록을 먼저 만든다. 기존 정책의 상세 재현은01·02(램프 감속),03·07(출발 차선변경),09·10(추종 충돌),13·14(복합 합류)를 우선하며, M3/M4의03·04·05·13·14·15 합류부도 모두 검사한다. 다음을 매0.2초 함께 기록한다.

1. AV와 충돌 상대의lane/위치/속도/길이,옆 차 포함 앞뒤 간격,이전·다음edge의 연결.
2. SUMO 원시 이웃값,정책에 전달된 정규화 관측,차량 존재 여부,음수gap처리,감지 범위 밖 여부.
3. 정책raw명령,양자화명령,실제차로변경,가속도,충돌상대ID. 명령과 실제 이동을 구분한다.
4. 속도/근접/막힘 등 보상 성분 합계,종료원인. 종료스텝에는 충돌/완주 보상만 적용하는 기존 규칙 검증.

각 M항목의 결과표에는 `확인된 사실 / 지지되는 원인 / 반박된 가설 / 미확인 / 다음 단독 비교`를 작성한다. 각 충돌은 초기 배치 문제, 횡방향 접촉, 앞차 추돌, 앞차 감속 연관, 관측 누락, 명령 적용 불일치를 다중 라벨로 기록한다. 예컨대 ‘램프 감속+관측 누락+늦은 제동’이 동시에 있으면 하나로 억지 분류하지 않는다. 원인 라벨 중복 합계와 상호배타적 종료 비율을 혼동하지 않는다.

수작업 합성 사례: 같은차로 접근/멀어짐,옆차 중첩,옆뒤 고속접근,차량없음,없는차로,연결edge의앞차. 관측에서 주변 차량의 전역 미래 경로·미래 행동·정답 차선명령을 사용하지 않는다.

**진행 조건:** 좌우 부호·속도 차 부호·차량 존재·좌표계·관측 길이·정책 명령 전달 검증을 통과해야 학습한다. 검출 오류가 있으면 별도 버그수정 커밋과 회귀검증 후 새 기준 버전을 고정한다. 오류가 남은 조건을 수십만스텝 돌리지 않는다. 행동 적용 자체의 오류가 발견되면 관측/보상 튜닝을 멈추고 사용자에게 먼저 보고한다.

## 1단계: 관측만 비교

모든 조건은 같은 기본 보상이다. 아래 추가값 정의는 검토용 제안이며 구현 전0단계 결과로 유효성을 확인한다.

| 실험 | 바꾸는 것 | 확인할 가설 |
|---|---|---|
| 기준 | 검증된 기존 관측+경로안내,추가채널0 | 트래픽에서 같은 예산으로 학습한 기준 성능 |
| 관측A:존재 여부 | 공통 검출기 수정 후 5차로×앞뒤 존재플래그10개만 추가 | 거리·상대속도에 존재 표시를 추가하면 근접 위험 학습이 개선되는가 |
| 관측B:접근위험 | 현재·좌·우 차로의 앞뒤접근위험6개. A는추가하지 않음 | 기존거리·상대속도로부터 위험을 배우기 어려웠는가 |

존재플래그는 실차 검출1/없음0,도로존재는 기존연결성으로 구별. 위험은앞차 `max(v_ego-v_front,0)/max(gap,epsilon)`,뒤차 `max(v_rear-v_ego,0)/max(gap,epsilon)`를TTC3초 기준으로0~1에clip. 겹침은위험1,멀어짐/차량없음은0,정지및분모0처리를명시한다. 반대방향·고가도로의XY근접차량은 제외한다. B는센서 검출 버그를 은밀히고치는 조건이 아니며,0단계에서 확정된 공통 검출기만 사용한다.

음수gap 누락이 실제 사례에서 확인됐으므로 수정은 모든 조건의 공통 기준으로 채택한다. 관측A는 추가 존재플래그만 비교한다. 수정 전 결과는 오류 재현으로 따로 보존한다. 공통 수정 및 32회 재현 검증을 완료했다. 음수 간격 45개 관측 채널이 가까운 차량으로 전달됐고, 무교통 16개 경로가 모두 완주했다. 기존 정책의 교통 조건 종료 결과는 변하지 않았다. 자세한 결과는 [공통 검출기 수정 검증](ic-neighbor-fix-20261114.md)을 참고한다.

## 2단계: 보상만 비교

먼저 기존관측 기준에서 아래를 **각각 단독으로** 비교한다. 관측 실험에서 좋은 결과가 나왔다고 기준관측을 중간에 바꾸지 않는다.

| 실험 | 단독 변경 | 목적 |
|---|---|---|
| 보상A:속도별차간거리 | 기존고정6m를 `2.5+1.5×v_ego`m로 교체. 벌점−0.1은유지 | 고속 접근을 더일찍억제 |
| 보상B:막힘벌점제거 | blocked_penalty0.05→0,다른항목유지 | 안전하게앞차를따라감속/대기하는행동이억제되는지 |
| 보상C:위험차선변경 | 요청한인접차로의 앞/뒤안전거리부족도를0~1로계산,−0.1×부족도×dt/1초 추가 | 급한끼어들기를억제하되 안전한변경은벌주지않기 |

보상C의 거리기준은앞 `2.5+1.5×v_ego`,뒤 `2.5+1.5×v_rear`. 단위는m,속도m/s. 선행/후행부족도중최댓값을사용하고,차량이없으면해당부족도0. 정책요청을막는필터가아닌보상만추가한다. 반복요청은dt적분으로처리해1회이벤트보상과섞지않는다. 계수0.1과1.5초는 **실측 정답이 아닌 초기실험제안**이다.

충돌벌점−5·도착+2·속도계수0.1은우선고정한다. 무작정충돌벌점을키우거나 차선변경전체를벌주는실험부터시작하지않는다. 추가조건과기준조건의총보상은서로다른목적함수이므로총보상크기로승자를정하지않는다.

## 3단계: 조합과 계수 확인

독립 실험에서 관측/보상 각각유효한항목이확인되면,기준·관측단독·보상단독·관측+보상 **2×2 비교**를동일조건으로실시한다. 단독효과와조합효과를구분한다. 여러보상을한꺼번에넣지않는다.

보상 성분이 속도·완주 보상을 압도하거나 아예 발생하지 않는 경우, 발생률·누적값·한 번당 값을 보고 해당 계수만0.5배/2배로 추가 비교한다. 관측 변경·학습률 변경과 동시에 하지 않는다. 회의 후속 항목은 M2의 제한속도, M3/M4의 지퍼, M5/M6의 분기·합류 준비로 각각 연결하며, 해당 진단을 생략한 채 보상만 추가하지 않는다.

- 1차 진단 목표: 완주·충돌 이외의 종료(시간초과, 잘못된 경로, 소실, 삽입 실패)를 0에 가깝게 줄인다. 충돌을 성공으로 처리하지 않는다.
