# 분기 통과 보상 +0.25 vs +1 · 600k 순수 PPO (팀원 담당분, pmh 실행, 2026-11-25)

상태: **완료**.

- 과제: jys3의 [팀원 담당 문서](../jys3-fork-reward-team.md)(`976d056`)를 그대로 실행했다.
- 실행 코드: `python -m utils.jys3_fork_reward_team` (jys3 커밋을 pmh에 병합한 `83c7ad6`). 코드는 바꾸지 않았다.

## 조건

- **보상**
  - 완주 +5, 충돌 −5로 고정했다.
  - 분기 통과 보상만 **+0.25**(`collision5`)와 **+1**(`collision5_fork1`)로 나눴다.
  - 그 밖의 보상: 경로 전진 보상은 한 주행 최대 +2, 일반 시간초과(1,000스텝)와 차로 끝 정지(30초)는 각각 −5, 속도 보상은 0이다.
- **학습**: 무작위 초기화에서 순수 PPO, 600,000스텝. 학습 seed는 11·22·33으로 조건마다 3개다. 고교통량 `high_real_ratio`, 16경로.
- **중간 평가와 선정**
  - 50,000스텝마다 seed별 64회를 평가했다(교통 seed 41110000대).
  - 조건마다 seed 3개를 합친 완주 수가 가장 많은 체크포인트를 고른다. 두 조건 모두 **600,000스텝**이 선정됐다.
- **최종 평가**
  - 학습·선정과 분리한 교통 seed 43110000대에서, seed당 64회씩 192회를 평가했다.
  - 두 조건은 같은 경로·출발 조건·교통 seed로 짝지어 평가했다.
- **실행 환경**: macOS 27.2.1 arm64, Python 3.10.21, PyTorch 2.14.0, NumPy 2.2.6, SUMO 1.27.1 (libsumo).
- **재현 확인 불일치**
  - 65,536스텝 가중치가 문서의 참조 가중치(원 실험 PC)와 6개 모두 다르다. `verified_*.json`의 `matched`가 false다.
  - PyTorch·NumPy 버전은 문서와 같다. 다른 것은 OS와 CPU(arm64 macOS)다. 부동소수점 연산 차이로 학습 궤적이 갈라진 것으로 보인다.
  - 따라서 아래 65,536스텝 결과는 원 단기 결과와 같은 가중치가 아니다. 두 조건은 같은 PC·같은 시작 가중치에서 비교했다.

## 해석

- **600k에서는 +1이 더 낫다.** 완주가 90에서 111건으로 늘고(+21), 충돌은 34에서 21건으로, 일반 시간초과는 22에서 5건으로 줄었다. 대신 차로 끝 정지가 46에서 55건으로 늘었다.
- **seed마다 결과가 다르다.** seed 11·22는 +1이 낫다(완주 +6, +22). seed 33은 +1이 더 나쁘다(완주 −7, 정지 37건).
- **초반에는 +1이 느렸다.** 학습 초반(50k~400k) 중간 평가에서는 +1의 완주가 +0.25보다 같거나 낮았다. 500k 이후에야 앞섰다.
- **분기 성공은 아주 조금 생겼다.** +1에서 16번 본선 복귀가 2/6건 나왔다. 13번 마지막 진출은 두 조건 모두 1/12건이다.
- **두 조건 모두 목표와 거리가 멀다.** 목표는 완주 95%, 충돌 5% 미만이다. 같은 지도에서 BC+DAgger 모델은 완주 95.7%, 충돌 0.8%였다([DAgger 수정 실험](../pmh-jys3-dagger-fix/README.md)).
- **원 PC 결과와의 비교는 주의해야 한다.** 가중치가 원 실험과 일치하지 않았다. 문서의 단기 결과와 위 65,536스텝 결과는 평가 seed도 다르다(41110000대와 43110000대). 따라서 직접 비교하지 않는다.
