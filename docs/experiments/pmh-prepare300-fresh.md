# pmh 분기 준비 보상 단독 비교

상태: 보상 단위 검사 및 libsumo 1.27.1에서 두 조건 × 2048스텝 학습/16경로 평가 통합 검증 완료. 본 실험 결과는 완료 후 추가한다.

기준 코드: cb753c04e8e3e3c00266bd2a528379624c40d601.
회의 모델 파일이 없어 사용자가 새 학습 비교를 선택했다. 회의 모델의 개선율을 재현하는 실험이 아니다.

- 대조군: 기존 보상. 수정군: 분기 300m 이내, 목적지 연결 차로까지 필요한 차로 변경 횟수가 한 단계 줄어들면 +0.1.
- 같은 edge/분기/목표 차로 집합/진척 단계에는 에피소드당 한 번만 지급. 정지 유지·멀어지는 이동에는 추가 보상 없음. 종료·충돌 스텝에는 추가 지급 없음.
- 두 군 모두 47차원 baseline 관측, 기존 300m 안내, 퇴계원 단독 지도, 저수요, warmup 300, best/max 출발, 기존 행동·안전 설정 유지.
- seed 11/22/33, 각 200000 스텝. 동일 seed는 동일 초기 state_dict를 사용한다. PPO 설정은 기존 계획의 hparams 사용.
- 평가: 보상 수정 없는 공통 환경, 무교통/저수요 각각 16경로 × 20개 seed(40001..40020). 완주·충돌·기타 실패와 경로별 원인을 기록한다.
- 지도·교통량·관측·TTC·안전거리 보상을 동시에 변경하지 않는다.
- 초기 가중치, 모델·지도 해시, 설정, 환경 버전, 진행 상황, 최종 평가를 results 아래 보존한다.

실행 전 짧은 검증:

```bash
python -m unittest discover -s tests -p test_prepare_reward.py
IC_LIBSUMO=1 python -m utils.pmh_prepare_trial --steps 2048 --seeds 11 --count 1 --workers 2 --output results/pmh_prepare300_smoke
```

통합 검증 후 본 실험:

```bash
IC_LIBSUMO=1 python -m utils.pmh_prepare_trial --workers 3
```

기존 결과 디렉터리는 덮어쓰지 않는다. 미완료 실행은 최종 결과로 보고하지 않는다.
판정은 동일 seed 대조군 대비 완주 증가, 충돌 비증가, 경로 선택 실패 감소 여부다.
새 학습의 짧은 예산에서 두 군 모두 실패하면 분기 보상이 무효라고 단정하지 않는다.

## 실행 환경

기존 `sumo-rl` 환경의 Python/PyTorch를 사용한다. 본 비교는 `libsumo`, `traci`, `sumolib`, `sumo-data` 모두 1.27.1로 맞춘다. `IC_LIBSUMO=0`이면 기존 SUMO 바이너리와 TraCI 소켓 방식을 사용할 수 있다. 두 군의 백엔드는 반드시 동일하게 둔다.

수업 기본 저장소는 실행 구조 참고 자료로만 사용한다. 수정 대상은 팀 저장소의 pmh이며, PPO·관측·교통·기존 보상은 pmh 기준을 유지한다. 보상은 기존 REWARD_OVERRIDES가 적용된 기본 step 반환값에 추가한다. 모델, CSV, TensorBoard, 실제 적용 설정과 소스 스냅샷을 보존한다.

## 2차: 분기 압박 벌점 추가 (prepare300_pressure)

처음 권장안 중 구현되지 않았던 "분기가 가까운데 차로 변경이 남아 있으면 벌점"을 추가한다. `env/prepare_reward.py`의 `PreparePressure`.

- 매 스텝 벌점 = 0.01 × 남은 차로 변경 수 × (1 − 분기까지 거리 / 300m). 목적지 연결 차로에 있으면 0, 300m 밖이면 0.
- 0.2초 스텝 기준, 분기 지점에서 한 차로를 남긴 채 약 100초 대기하면 충돌 벌점 5.0과 같아진다. 그보다 크게 하면 무리한 끼어들기를 학습할 위험이 있어 0.01로 시작한다.
- 종료·충돌 스텝, 교차로 내부 lane에는 부과하지 않는다. 진척 보상(+0.1)은 그대로 유지한다.
- 3개 조건(baseline, prepare300, prepare300_pressure)을 같은 초기 가중치로 다시 학습해 비교한다.

```bash
IC_LIBSUMO=1 python -m utils.pmh_prepare_trial --workers 9 --output results/pmh_prepare300_pressure
```

판정: 무교통 `route_lane_blocked` 감소, 저교통 완주 증가, 충돌 비증가. 충돌이 늘면 무리한 끼어들기로 보고 가중치를 낮춘다.

## 4차: 차로 변경 위험 벌점 (pressure_lcrisk, 2026-11-15)

압박 0.01 조건에 실행된 차로 변경의 위험 벌점을 더했다. 벌점 = 0.5 × 위험도. 위험도는 목표 차로 앞뒤 차량의 간격(5m 미만)과 TTC(3초 미만) 중 나쁜 쪽이다. 안전 게이트는 끈 상태를 유지했다. 결과: `results/pmh_pressure_lcrisk`.

| 조건 | 무교통 완주율 | 저교통 완주율 | 저교통 충돌률 | 저교통 차로 선택 실패 | 차로 변경 직후 충돌(근사) |
|---|---:|---:|---:|---:|---:|
| 압박 0.01 | **63.44%** | **57.19%** | 23.12% | **12** | 75 |
| 압박 0.01 + 위험 벌점 | 24.69% | 42.08% | 22.60% | 118 | **27** |

저교통 seed별 완주/충돌(11/22/33): 압박 0.01은 203/98, 135/56, 211/68. 위험 벌점 추가는 163/90, 168/34, 73/93.

- 차로 변경 직후 충돌은 75→27건으로 줄었다. 하지만 같은 차로 충돌이 약 147→190건으로 늘어 전체 충돌률은 거의 같다.
- 차로 선택 실패가 12→118건으로 다시 늘었다. 무교통 완주율도 63%→25%로 떨어졌다. 무교통에서는 위험 벌점이 0인데도 떨어졌으므로, 저교통 학습에서 "차로 변경 자체가 비싸다"를 배워 차로 변경을 주저하게 된 것으로 본다.
- seed 33은 학습 말기 평균 보상이 -2.78로 학습이 무너졌다.

결론: 위험 벌점 0.5는 채택하지 않는다. 압박 0.01을 현재 최선으로 유지한다. 남은 충돌의 대부분은 같은 차로 추돌이므로, 다음 독립 실험은 앞차 접근 위험(상대속도·TTC) 벌점이다. 차로 변경 위험 벌점을 다시 시도한다면 0.1 이하의 작은 가중치로 비교한다.

## 5차: 추돌 위험(TTC) 벌점 (pressure_ttc, 2026-11-15)

압박 0.01 조건에 같은 차로 앞차 접근 벌점을 더했다. 매 스텝 벌점 = 0.05 × clip((3초 − TTC)/3초, 0, 1)이다. 관측 거리 50m 안의 앞차에만 적용하고, 내가 더 빠를 때만 준다. 충돌 스텝은 제외한다. 결과: `results/pmh_pressure_ttc`.

| 조건 | 무교통 완주율 | 저교통 완주율 | 저교통 충돌률 | 같은 차로 충돌 | 차로 변경 직후 충돌 | 저교통 차로 선택 실패 |
|---|---:|---:|---:|---:|---:|---:|
| 압박 0.01 | **63.44%** | **57.19%** | 23.12% | 147 | 75 | **12** |
| 압박 0.01 + TTC 벌점 | 50.00% | 51.88% | **19.58%** | **121** | 67 | 198 |

저교통 seed별 완주/충돌(11/22/33): 압박 0.01은 203/98, 135/56, 211/68. TTC 추가는 139/49, 195/96, 164/43.

- 충돌은 222→188건으로 줄었고, 같은 차로 충돌도 147→121건으로 줄었다. 다만 seed 22는 충돌이 56→96건으로 늘어 seed 간 방향이 일관되지 않다.
- 차로 선택 실패가 12→198건으로 다시 늘어 완주율은 5.3%p 떨어졌다. 10·11·14번 경로가 다시 막혔다.
- 4차(차로 변경 위험)와 같은 패턴이다. 압박 벌점 위에 벌점 항을 하나 더 얹으면 분기 차로 준비 학습이 흔들린다. 200k 스텝·3 seed에서는 seed 편차가 효과 크기와 비슷하다.

결론: TTC 벌점 0.05는 충돌을 다소 줄이지만 완주율을 낮추므로 아직 채택하지 않는다. 추가 보상 조정 전에 압박 0.01 결과(57%)가 seed를 늘려도 유지되는지부터 확인한다. 또 학습 예산을 늘렸을 때 두 신호를 함께 학습할 수 있는지도 확인한다.

- 더 오래 학습해도 좋아지지 않았다. 압박 0.01은 완주율이 57%→42%로 떨어졌다. 압박 + TTC는 차로 선택 실패가 0건이 됐지만, 충돌률이 20%→39%로 두 배가 됐다.
- seed 11은 두 조건 모두 600k 시점의 학습 평균 보상이 음수로 무너졌다(압박 −0.49, 압박 + TTC −2.57). 학습이 단조롭게 개선되지 않고 진동한다.
- 따라서 "마지막 체크포인트 한 시점"의 평가는 그 시점의 진동에 크게 좌우된다. 200k 결과의 우열도 이 진동 안에 있을 수 있다.

결론: 학습 예산을 늘리는 것만으로는 해결되지 않는다. 보상을 더 바꾸기 전에 평가 방법부터 고친다. 저장된 체크포인트(약 50k 간격)를 여러 시점에서 평가해 학습 곡선을 비교하고, 고정된 검증 기준으로 체크포인트를 선택한다. 학습 불안정에는 PPO 설정(학습률 감소 등)을 별도 실험으로 확인한다.

1. 검증 seed(예: 50001~)로 체크포인트를 고르고, 기존 평가 seed(40001~40020)로 최종 비교한다.
2. 학습률 감소 등으로 400k 이후 붕괴를 막는 PPO 설정 실험을 한다.
