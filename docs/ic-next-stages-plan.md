# 수정 맵 후속 자동 실험

사용자가 승인한 순서: HV 검증 → 기존 AV 트래픽 진단 → 16경로 공유 정책 → 저수요/기본수요 학습 → 보상 독립 비교. 기존 실험은 보존한다.

## 실행 전 결정 (구현자의 선택)

- 맵 및 기존 행동 제약 고정, 강제 경로 보정 0회. N0와 N1을 공유 정책에서 비교한다. N2는 04/14에서 N1보다 완주 개선이 없어 이번 확장에서는 제외한다.
- 현재 맵에 맞는 실측 수요가 없으므로 합성 수요임을 명시한다. 각 진입 차로당 기본 600대/시간, 저수요 300대/시간. 같은 입구의 가능한 경로에 균등 배분한다. 전체 저수요 5,100대/시간, 기본수요 10,200대/시간. AV 투입 전 트래픽을 60초 흐르게 하고 무교통은 기존 20초를 유지한다. 옛 22경로의 14,420대/시간과 같다고 주장하지 않는다.
- 승용차 제어기 기존 비율, 버스 5%, 승용차 중 위반형 2%(전체 기대 비율 1.9%). 기존 custom1 실선 변경 권한만 유지한다. 실제 발생 비율도 기록한다.
- **현재 수정 맵에는 옛 사노 지퍼 junction/보상 위치가 없다.** 현재 맵의 우선권 및 SUMO 협조 차로 변경을 그대로 검증하며, 이를 지퍼합류 구현 완료라고 부르지 않는다. ZIP 보상은 새 지점·판정 검증 전 실행 금지.
- 학습 전 각각 2,048스텝 smoke. 공유 정책은 각 조건·seed당 800,000스텝(16경로 확장을 위한 별도 동일 예산), seed 11/22/33. 원본 PPO·보상·학습률 유지. 모든 모델 새 초기화; 트래픽 단계는 해당 무교통 모델 가중치부터 추가 학습하며 optimizer는 새로 시작한다.
- 모델 평가 seed는 학습과 별도. 경로별 20회, 세 학습 seed 모두 경로별 완주율 ≥95%, 충돌률 <5%일 때만 다음 학습 단계로 진입. 이 기준은 개발 검증이며 최종 holdout의 통계 보증이 아니다.
- 실패하면 원인별 표와 마지막 60초 추적을 남기고 의존 단계는 차단. 성능 미달을 숨기고 다음 단계나 대량 수집으로 넘어가지 않는다.

## 단계 및 중단 조건

1. HV: low/base 각각 seed 1001/1002/1003, 유입 900초 + 배출 900초. 실제 삽입률 ≥95%, 삽입 차량 완주율 ≥95%, 충돌/텔레포트 0. 수요별로 통과한 경우에만 해당 수요의 AV 진단을 진행한다. 저수요가 통과하면 무교통 공유 정책과 저수요 학습은 독립적으로 계속할 수 있다.
2. 기존 AV: 04/14 × N0/N1/N2 × 학습 seed3 × low/base × 평가 seed5. 정책 재학습 없이 양쪽 통과 시 총180회, 저수요만 통과 시90회. 성능 실패 자체는 다음 무교통 학습을 막지 않되, 시뮬레이터 오류는 중단한다.
3. 공유 정책: N0/N1 × seed3 ×800k, 무교통 16경로 평가. N1 세 seed가 모두 기준을 통과해야 트래픽 학습 진행. N0 결과도 모두 보고한다.
4. N1 저수요 추가800k → 평가 → N1 기본수요 추가800k → 평가. 단계마다 세 seed 전부 통과해야 다음으로 이동.
5. 보상 변경은 고정된 기본수요 N1에서 ROUTE100, RAMP를 각각 추가800k 비교하며 대조군도 같은 추가800k 학습. ZIP은 현재 맵의 이벤트 정의 미검증으로 자동 실행하지 않는다. 따라서 최종 보상 조합·최종 수집은 별도 검증 전 보류한다.

## 구현·검증 기록

- [x] 합성 수요 생성, 구성·유량·맵 고정 검사
- [x] 초기 트래픽 smoke 및 저장 모델 평가 경로 확인
- [ ] HV 검증과 단계별 결과 발행
- [ ] 자동 학습·평가 순차 실행

실행: `python -m utils.navigation_followup`. 로컬 `results/navigation_followup_v2/`; 요약 `docs/ic-next-stages-results.md`. 완료 단계마다 전용 문서만 커밋·push. 실행 잠금, 원자료 보존, 디스크 20GiB 하한. 추가 수집은 이번 실행 범위에 포함하지 않는다.

대안: 즉시 보상 전수 재실험은 원인 혼합 때문에 제외. 경로별 모델16개는 공유 정책 검증이 아니므로 제외. 사용자가 승인한 단계적 검증을 채택했다.

검토 보완: 캐시 파일/모델/코드 해시 불일치는 재사용을 거부한다. ROUTE100/RAMP 비교에는 준비 성공률, 램프 과속 스텝 비율, 보상 성분 합계를 별도로 기록한다. 오류를 수정하며 수행한 초기 smoke는 그대로 보존하고 최종 smoke-v2를 구분한다.

## 첫 HV 결과 및 실행 분리

v1: 저수요는 3개 seed 각각 1,278/1,278 완주, 충돌·텔레포트0. 기본수요는 예정2,552대 중 삽입2,342/2,347/2,344대(약91.8~92.0%)여서 삽입률95% 기준 미달. 미삽입은 주로 동일 입구의 route13/14/15에 집중했다. 이는 AV 정책의 실패가 아니다. 대기 원인은 추가 분석 대상이며 아직 도로 오류로 확정하지 않는다.

Ruling: 기본수요 검증 실패가 무교통 및 이미 통과한 저수요 실험까지 막는 의존관계를 수정한다. 수요를 몰래 낮추거나 통과 기준을 완화하지 않는다. v1 결과를 보존하고 v2에서 동일 HV 검증을 재현한 뒤, 통과 수요만 기존 AV 진단으로 진행한다. 공유 정책/저수요 기준 통과 후에도 기본수요가 미달이면 기본수요 학습과 보상 비교는 차단한다.
