# 5차 회의 공유안 — 퇴계원IC 분산 실험 계획

작성일: 2026-11-13 · 상태: 회의 배정 및 일정 확정 전

**경로 안내만 적용한 PPO를 공통 기준으로 삼고, 기능을 하나씩 바꿔 여러 컴퓨터에서 독립 비교한다. 1차에는 경로 선택 실패와 비정상 종료를 없애고, 최종적으로 충돌률을 5% 미만으로 낮춘다.**

## 1. 목표와 진행 순서

| 단계 | 목표 | 통과 조건 |
|---|---|---|
| 사전 검증 | 도로·트래픽·평가기 확인 | 16개 경로 연결, HV 정상 주행, 종료 원인 기록 확인 |
| 1차 — 경로 선택 | 출구를 놓치거나 길을 찾지 못하는 문제 해결 | 무교통 정상 완주율 100%. 이후 저수요에서 기타 실패율 0% |
| 최종 — 안전 주행 | 경로 선택 능력을 유지하면서 충돌 감소 | 저수요에서 기타 실패율 0% 및 충돌률 <5%. 검증 후 교통량 확대 |

평가 에피소드는 중복 없이 세 가지로 분류한다.

- **정상 완주:** 지정 출구에 충돌 없이 도착.
- **충돌 종료:** AV 충돌로 종료. 충돌과 도착이 동시에 기록되면 충돌로 분류.
- **기타 실패:** 잘못된 출구, 차로 끝 정지, 시간 초과, 삽입 실패, 텔레포트, 프로그램 오류 등. 원인을 세분화하며 평가에서 조용히 제외하지 않는다. 프로그램 오류가 있으면 유효한 평가 완료로 판정하지 않는다.

`정상 완주율 + 충돌 종료율 + 기타 실패율 = 100%`

**1차의 트래픽 목표는 정상 완주율+충돌 종료율=100%지만, 충돌로 경로 실패가 가려질 수 있으므로 무교통 100% 검증을 함께 요구한다.** 충돌 전에 남은 경로를 주행할 수 있었는지는 확인되지 않는다. 1차 통과를 안전성 달성으로 표현하지 않는다.

최종 조건을 만족하면 정상 완주율은 95%를 초과한다. 모든 비율은 전체 합산과 경로별·학습 seed별로 함께 보고한다. 개발 통과는 각 경로·각 seed에서 판정한다.

수업 최종 평가 문서는 충돌률 **5% 미만**과 정상적인 목적지 완주, 충분한 HV와의 상호작용을 요구한다. 무교통 100%, 경로별·seed별 통과는 **팀 내부 검증 기준**이다. 소개 문서에는 5% 이하로 표기되어 있어 확인 전까지 더 엄격한 최종 평가 문서를 따른다.

## 2. 공통 기본 조건 — 경로 안내만 적용

| 영역 | 모든 팀원이 사용할 기준 |
|---|---|
| 도로·경로 | 확정된 퇴계원IC 맵 한 버전, 16개 경로. 에피소드당 지정 경로 하나 |
| 주변 관측 | AV 속도, 차로별 선행·후행 차량 거리·상대속도, 차로 연결성·밀도 |
| 경로 안내 | 다음 도로로 갈 수 있는 차로의 상대 방향, 준비 지점까지 거리, 준비할 차로의 상대 방향 |
| 행동 | 종방향 가감속 + 횡방향 좌·유지·우 차선변경. 강제 경로 보정 없음 |
| 보상 | 기존 속도·근접·막힘·충돌·도착 보상 유지. 목적지 차로 추가 보상 없음 |
| PPO | 학습률0.0003, 감마0.99, clip0.2, rollout2048, epoch10, minibatch64 |
| 탐험 | 차로 탐험 계수0.01 고정. 후반 탐험 감소 없음 |
| 모델 | 기존 제공 PPO와 정책 구조 유지. BC·BC+PPO는 이번 독립 비교와 분리 |
| 시작점 | 경로 안내만 적용한 공통 체크포인트. seed11·22·33에 대응하는 파일을 동일하게 배포 |
| 반복·예산 | seed11·22·33. 1차 비교 추가20만 스텝, 5만마다 평가를 제안. 확대 시 비교군 예산 통일 |
| 에피소드 | 충돌 또는 도착 시 종료. 상한900초는 시간 초과로 별도 기록 |
| 교통 | 무교통과 저수요를 분리. 저수요는 합성 수요5100대/시간, 평가 전60초 교통 준비 |

기본 보상 수치: 속도 `0.1×현재속도/기준속도`, 차간거리6m 미만 `−0.1`, 간격20m 미만·기준속도70% 미만일 때 막힘 `−0.05`, 충돌 `−5`, 도착 `+2`. 차선변경 및 실행 불가능 명령 벌점은0. 충돌·도착 스텝에는 해당 종료 보상을 적용한다.

**배포 전 필수 확정:** 공통 커밋, 맵·모델 해시, 체크포인트 스텝, 실제 관측 구성, 평가 출발 조건, 평가 seed 목록. 기존 경로 안내 기준 구현은 37개 관측에 비교용0값10개를 붙인47차원 정책 입력을 사용한다. 단순히 ‘47차원’이라는 이유로 다른 관측 모델과 호환된다고 판단하지 않는다.

학습은 원래 설계에 따라 가중치에서 시작하고 optimizer는 새로 초기화한다. 관측 확장 실험은 초기화·가중치 이전 방식을 따로 기록하며, 추가 학습 전 공통 관측에서 초기 행동이 변하지 않는지 확인한다.

## 3. 팀원별 분담안

담당자 이름과 PC는 회의에서 확정한다. 인원이 부족하면 한 사람이 순차적으로 두 작업을 맡고, 가용 PC가 많으면 같은 조건의 seed를 나눈다.

| 작업 | 담당 / PC | 기준군 대비 변경 | 핵심 제출 결과 |
|---|---|---|---|
| 총괄·공통 기준 | 성지용 / 중앙 비교 | 설정 배포·버전 고정·결과 통합 | 작업 명세, 공통 평가표, 다음 실험 배정안 |
| A. 기준 재현 | 회의 배정 | 변경 없음 | 16경로 실패 위치·원인, 컴퓨터 간 재현 확인 |
| B. 차로 준비 보상 | 회의 배정 | 목표 차로에 가까워지는 보상만 추가 | 분기 놓침·차로 끝 정지·완주 변화 |
| C. 관측 정보 | 회의 배정 | 안내 유효 여부 또는 다음 분기 정보. 둘은 별도 실험 | 안내 누락·오류 여부, 차로 선택 변화 |
| D. 탐험 일정 | 회의 배정 | 차로 탐험 계수 감소만 적용 | 중간 최고와 최종 성능, 후반 성능 하락 |
| E. 환경·평가 검증 | 회의 배정 | 비교용 학습 맵은 고정하고 수정안 별도 관리 | HV 수요 배분, 버스 차로, 합류 이벤트 정의 |

**A→B→C처럼 기능을 누적하지 않는다. B·C·D는 모두 A에서 하나씩만 바꾼다.** 효과가 확인된 이후 조합 실험을 진행한다. C의 관측 두 항목도 동시에 켜지 않는다.

1차 선정 조건이 확정되면 다음 안전 실험을 다시 배정한다.

| 최종 목표 단계 | 변경 기능 | 평가할 효과 |
|---|---|---|
| 안전 기준군 | 1차 선정 조건 유지 | 비교 기준 확보 |
| 접근 위험 관측 | TTC·필요 감속도 정보 추가 | 앞차 접근 시 조기 감속 |
| 정상 추종 보상 | 안전한 추종·대기에서 막힘 벌점 제외 | 무리한 가속·추월 감소 |
| 위험 접근 벌점 | 상대속도·간격에 따른 위험 벌점 | 늦은 감속·추돌 감소 |
| 조합 | 효과가 확인된 기능 결합 | 충돌 감소와 경로 완주 능력 동시 유지 |

충돌률이 줄더라도 시간 초과나 경로 실패가 증가하면 최종 목표 통과가 아니다.

## 4. 실험 운영과 하루 마감

- `main`은 검증된 공통 버전으로 유지한다. 실험은 같은 기준 커밋에서 만든 `codex/exp-주제` 브랜치에서 진행한다.
- 실행 중 공통 코드·맵을 변경하거나 pull하여 조건을 바꾸지 않는다. 환경 수정이 필요하면 새 버전으로 구분하고 기준군부터 재평가한다.
- 각 PC에서 동일 저장 모델의 짧은 평가를 먼저 실행한다. Python·PyTorch·SUMO 버전과 설정·결과 차이를 확인한 후 긴 학습을 시작한다.
- 코어 수와 실제 처리속도를 측정해 동시 작업 수를 정한다. 빠른 PC는 더 많은 작업을 맡고, 결과 비교는 실행시간이 아닌 동일 스텝 기준으로 한다.
- 첫 비교 추가20만·5만 간격 평가 후 동일 예산으로 확대한다. 예산은 회의에서 확정한다.
- 매일 결과 취합 시각까지 완료 결과와 미완료 진행률을 함께 제출한다. 중간 결과를 최종 결과처럼 비교하지 않는다.
- 개발 평가로 모델을 선택하고, 선정에 사용하지 않은 별도 평가 조건으로 최종 확인한다.

| PC별 실행 검증 완료 | 시각: ___ |
| 1차 결과 제출 | 날짜·시각: ___ |
