# 퇴계원IC 단계별 개발 및 독립 비교 실험 설계

작성일/수정일: 2026-11-03. 상태: **설계만 작성, 실험 미실행**. 수업 원본 2e01bbacebb978a9d3122b7cc3d05b1f80dcbf65의 준비·평가·컨설팅 문서를 반영했다.
사용자 확인: 영훈님 맵은 kyh 브랜치가 맞으나 업로드가 아직 끝나지 않았다. 참고 커밋은 34057b4이며 최종 기준 커밋은 미정이다. 맵 병합·학습 코드 수정·학습 실행은 하지 않는다. 수업 자료와 이 설계 문서의 main 반영은 별도 승인된 문서 작업이다.

## 1. 목적과 실험 단위

- 한 에피소드 = AV 한 대가 지정된 출발지에서 목적지까지 이동. 완주·충돌·시간 초과 등으로 종료한다.
- 경로별로 에피소드를 분리하지만 **하나의 PPO 정책**을 공유한다. 경로마다 별도 모델을 만드는 것이 아니다.
- 학습 에피소드는 경로를 균등하게 섞고 교통량과 HV 배치를 바꾼다. 경로 선택용 난수와 HV 생성용 난수는 분리한다.
- 합류 직전만 잘라 시작하지 않고, 사전 차선 선택에 충분한 접근 구간을 포함한다.
- 참고 맵 문서는 13개 경로를 명시한다. 최종 맵에서 유효한 출발·출구 조합을 확인해 R01~RN으로 등록한다. 15개라고 가정하지 않는다.
- 모든 경우 무충돌 완주는 전체 평가 묶음의 목표다. 모든 경로를 한 에피소드에 이어 붙이지 않는다.
- 별도 경로 모델, 순차 미세조정 대신 **동일 초기화 조건에서 독립 학습**을 기본 비교 방식으로 채택한다. 미세조정은 추가 연구로 분리한다.

## 2. 두 종류의 기록을 구분한다

1. 개발 단계: 맵 → HV 합류 → 현실적인 교통 구성 → AV 보상 → 학습 파라미터 순으로 누적한다.
2. 원인 비교: 공통 기준에서 한 변수만 바꾼다. 개선된 항목을 차례로 덧붙인 결과만으로 개별 효과를 주장하지 않는다.

성공한 결과뿐 아니라 변화 없음, 악화, 구현 오류, 예산 부족도 기록한다. 예전 jys 도로의 결과를 새 kyh 도로의 결과로 옮겨 쓰지 않는다. 이미 존재하는 변경을 새로 개발한 것처럼 과거 커밋을 재구성하지 않는다.

## 3. 단계 1~3: 학습 환경 확정

| 단계/ID | 변경 | 비교 기준 | 주요 평가 |
|---|---|---|---|
| S1 | 최종 kyh 맵을 main에 병합하고 승용차 기본 교통을 별도 설정으로 고정 | 최종 맵 및 원래 교통 설정 보존 | 경로 연결, 삽입 실패, 도착, 대기, 충돌, 텔레포트 |
| S2-Z | 지정 합류부의 우선권만 zipper로 변경 | S1 | 램프 대기시간, 처리량, 대기열, 급제동 |
| S2-C (필요시) | HV 차선 변경 협조성만 변경 | S1 또는 명시적으로 고정한 S2-Z | 합류 성공과 본선 지연의 균형 |
| S3-B | 버스 비율 0% → 5% | 채택한 S2, 위반 차량 0% | 대기·처리량·차량 유형별 영향 |
| S3-V | 비버스 HV 중 위반 가능 차량 0% → 5% | 채택한 S2, 버스 0% | 실제 실선 위반 빈도, 급제동, 충돌 |
| S3-BV | 버스 5% + 비버스 HV 중 위반 가능 차량 5% | S2/S3-B/S3-V | 두 요소를 합쳤을 때의 영향 |

- 최종 kyh 맵에서 병목을 먼저 재현한다. 참고 맵 문서에는 병목이 크게 줄었다고 기록되어 있다. 필요 없는 zipper 변경을 효과가 있는 것처럼 채택하지 않는다.
- S2-Z에서는 가시거리·협조성·교통량을 동시에 바꾸지 않는다. 필요하면 각각 별도 실험으로 둔다. 기존 jys의 노드 ID를 새 맵에 그대로 적용하지 않는다.
- zipper는 합류 지점 통행 우선권 설정이다. 기존 차량 추종 모델을 새로 작성하는 작업과 구분하고 실제 도로와 다른 가정이면 명시한다.
- 버스와 위반 차량을 동시에 추가한 결과만으로 각각의 영향을 주장하지 않는다.
- S3는 전체 차량 투입 일정·경로·수요를 고정하고 차량 유형 또는 위반 권한만 교체한다. 버스의 차체 길이 차이는 실험 처리의 일부다.
- 위반 차량은 실선 차선 변경을 허용하되 안전 간격 검사를 유지하는 현재 아이디어를 출발점으로 한다. 과속·강제 끼어들기를 포함한다고 표현하지 않는다.
- 차량 ID와 seed로 유형을 결정해 실험 간 대응을 유지한다. 정책에 따라 이후 차량 궤적은 달라질 수 있다.
- 저/중/고 수요는 최종 맵 용량 점검 후 사전 고정한다. 이전 jys의 2,920대/시간을 그대로 이전하지 않는다.
- 1,800초 수요 + 최대 600초 배출을 후보로 삼고 동일한 5개 seed로 반복한다. 부하별 결과와 미삽입 차량을 별도로 집계한다. 텔레포트로 병목을 숨기지 않는다.
- S3-BV의 채택 설정을 환경 E0로 고정한 뒤 보상 실험으로 넘어간다.

## 4. 학습 비교 전 공통 구현 조건

보상 실험 전에 아래 기능을 모든 실험에 동일하게 넣고 고정한다. 새 보상을 추가할 때 관측까지 함께 바꾸면 보상만의 효과가 아니다.

- 경로 선택과 올바른 목적지 도착 판정. 잘못된 출구 도착, 텔레포트, 비정상 소실을 성공으로 처리하지 않는다.
- 경로상 다음 합류까지 거리, 목적지와 연결되는 차선, 합류 상대 차량의 위치·속도, 실선 여부, 구간 목표 속도 등 필요한 관측을 모든 조건에 동일하게 제공한다.
- 거리와 간격은 AV가 감지할 수 있는 정보로 구성한다. 평가용 전체 상태를 정책 입력에 몰래 사용하지 않는다.
- 합류 이벤트·보상 항목별 로그, 고정 평가 목록, checkpoint 저장 기능을 먼저 검증한다.
- E0에서는 AV를 한 대만 투입하고 시연용 ego_demo는 제외한다.
- 초기 학습 기준: PPO hybrid 정책, MLP (256,256), lr=3e-4, gamma=0.99, n_steps=2048, n_epochs=10, minibatch_size=64. 나머지도 설정 전체를 저장한다.
- 시뮬레이션/AV 결정 간격은 0.2초를 제안값으로 두되 통합 검증 후 확정한다. 이후 모든 비교에서 고정한다.
- 기존 0.5초 기준의 지속 보상·벌점은 dt/0.5를 곱해 초당 크기를 보존한다. 충돌·도착·합류 이벤트 같은 일회성 보상은 시간 간격으로 축소하지 않는다.
- 시간 초과는 모든 조건에 공통인 경로별 한도로 설정한다. 경로 자유주행 시간과 비학습 주행 시험을 보고 학습 전에 확정하며, 결과를 보고 특정 실험만 늘리지 않는다.
- 경로/부하별 학습 배분을 동일하게 고정한다. 어려운 경로를 더 자주 뽑는 커리큘럼은 이후 별도 실험으로 둔다.

## 5. 단계 4: 보상을 독립적으로 비교

R0는 기존 보상 항목을 유지한 기준이다. 위 시간 정규화와 새 맵 연결은 모든 조건 공통이다. 아래 각 행은 **R0에서 해당 항목 하나만 변경**하며 앞 행의 변경을 누적하지 않는다.

| ID | 유일한 변경 | 기준 → 후보 | 가설/주요 부작용 |
|---|---|---|---|
| R0 | 없음 | 속도 .1, 근접 6m/.1, 막힘 .05/20m/.7, 충돌 5, 도착 2, 변경 벌점 0 | 기준 |
| R-BLOCK | 막힘 벌점 계수 | .05 → 0 | 정상 양보에 대한 불이익 감소 / 불필요한 정지 증가 가능 |
| R-SPEED | 속도 보상 기준 | 전역 vmax → 구간 목표 속도, 보상비율 최대 1 | 램프 과속 유인 완화 / 과속 억제 자체를 보장하지 않음 |
| R-GAP | 근접 판정 거리 | 고정 6m → 2.5m+1.0초×속도 | 고속 추종 간격 개선 / 끼어든 차량 때문에 벌점 증가 가능 |
| R-COLL | 충돌 벌점 계수 | 5 → 10 | 충돌 감소 / 소극적인 정지 증가 가능 |
| R-ARR | 완주 보너스 | 2 → 5 | 완주 유인 증가 / 희소 보상이라 효과가 약할 수 있음 |
| R-LC | 차선 변경 벌점 | 0 → .02/실제 변경 이벤트 | 불필요한 지그재그 감소 / 필요한 변경 위축 가능 |
| R-PREP | 합류 사전 준비 보상 추가 | 0 → 최대 +.1/합류 이벤트 | 늦은 차선 변경 감소 / 유리한 상태만 찾아다니는 악용 점검 |
| R-ZIP | 지퍼 준수/위반 항목 추가 | 0 → 준수 +.1, 귀책 위반 −.1/이벤트 | 순서 준수와 양보 개선 / 과도한 양보 가능 |

R-GAP에서는 판정 거리만 바꾸고 벌점 .1과 이진 판정은 유지한다. 연속 벌점으로 바꾸는 실험은 별도다. R-SPEED에서도 과속 벌점까지 동시에 넣지 않는다. R-ZIP의 준수/위반은 하나의 기능 패키지 효과이며 두 계수의 독립 효과로 해석하지 않는다. 필요한 경우 +보상만/−벌점만 조건을 추가한다.

### 5.1 ‘100m 전 준비’의 정의

- 합류점까지 **예정 경로를 따라 잰 잔여 거리**를 사용한다. 지도상 직선거리로 판정하지 않는다.
- 100m는 준비 구간의 시작 후보이지, 그 지점에서 강제로 끼어들라는 명령이 아니다.
- 유효한 접근 구간을 가진 합류만 평가한다. 생성 시점부터 이미 100m 이내인 경우를 실패로 간주하지 않고 제외 건수를 기록한다.
- 점선과 안전 간격 조건 안에서 올바른 연결 차선을 확보하거나, 상대 차량 순서에 맞는 속도·간격을 만드는 상태를 준비 상태로 정의한다. 거리만 가까워졌다고 보상하지 않는다.
- 이벤트당 보상은 최대 +.1로 제한한다. 준비 구간에서 왕복하거나 매 스텝 기다려 보상을 반복 획득하지 못하게 한다.
- 처음부터 준비가 완료된 사례와 정책 행동으로 준비를 완료한 사례를 구분한다. 시작 조건만으로 성능이 좋아 보이지 않게 한다.
- 정량 판정에 필요한 목표 간격·속도 범위는 비학습 주행으로 확인하고 학습 전에 설정 파일로 고정한다.
- R-PREP가 유망하면 P50/P100/P150을 동일한 R-PREP 설정에서 비교한다. 이때 **준비 거리만** 변경하고 보상 크기는 고정한다. 짧은 램프는 가용 접근 길이를 별도 보고한다.

### 5.2 ‘AV 지퍼 합류’의 정의

- 양쪽 유입에 대기 차량이 있고 충돌하는 합류 동작일 때만 순서 준수를 판정한다. 상대 차량이 없으면 즉시 진행해도 위반이 아니다.
- 동일한 관측 가능한 규칙으로 합류 순서를 정하고 이벤트 중 대상 차량을 고정한다. 반복 재배정으로 점수를 얻지 못하게 한다.
- AV 차례에 안전하게 합류하거나, 상대 차례에 필요한 양보를 수행하고 이벤트를 마치면 준수로 기록한다. 양보 시간에 비례해 무한 보상하지 않는다.
- 안전하게 양보할 수 있었는데 AV가 순서를 빼앗은 경우만 귀책 위반으로 기록한다. HV의 무리한 끼어들기·비정상 정지는 AV의 위반으로 세지 않는다.
- 필요한 안전 검사를 유지한다. 제어기가 이미 강제하는 행동만 보상하면 학습 효과가 거의 없을 수 있으므로 실제 AV 명령과 적용 행동을 함께 기록한다.
- 다른 차량의 급제동은 관찰 지표로 먼저 사용한다. AV 때문에 발생했다고 판정할 근거가 없으면 곧바로 AV 벌점에 넣지 않는다.
- zipper 네트워크 설정은 R0~R-ZIP 모두 동일하게 고정한다. R-ZIP에서 도로 우선권까지 함께 바꾸지 않는다.

### 5.3 조합 확인

개별 효과가 확인된 항목만 모은 R-COMB를 별도로 학습한다. 개별 개선이 합쳐져도 좋아지는지 검증한다. 자원이 허용하면 R-COMB에서 준비 보상만 제거한 조건, 지퍼 보상만 제거한 조건을 추가해 조합 안에서의 기여도도 확인한다. 독립 실험과 조합 실험의 결론을 구분한다.

## 6. 단계 5: 학습 파라미터 독립 비교

선택한 보상 R*와 환경 E0를 확정한 다음 진행한다. R* 선택에 사용한 평가 자료를 최종 성능 검증 자료로 재사용하지 않는다.

| ID | lr | gamma | 비교 대상 |
|---|---:|---:|---|
| H0 | .0003 | .99 | 기준 |
| H-LR | .0001 | .99 | H0: 학습률만 변경 |
| H-GAMMA | .0003 | .995 | H0: 감마만 변경 |
| H-COMB (후속) | 선택 lr | 선택 gamma | 두 설정 조합의 효과. 개별 효과와 구분 |

- 모두 같은 초기화 seed에서 처음부터 학습한다. H0 모델에서 이어 학습하지 않는다.
- 같은 모델 구조·학습 예산·경로 배분·평가 조건을 사용한다. gamma 실험 중 dt를 바꾸지 않는다.
- lr은 업데이트 크기와 안정성, gamma는 미래 보상에 대한 할인 정도를 바꾸는 가설이다. 좋아질 것이라고 미리 결론내리지 않는다.
- 선택적으로 lane_entropy_coef=.01과 .005 비교를 다음 단계로 둘 수 있으나 1차 필수 실험에는 포함하지 않는다.

## 7. 학습 예산과 평가

### 공통 예산

- 기능 점검: 조건별 10,000스텝, seed 1개. 로그·종료·보상 계산 오류를 확인하며 성능 결론을 내리지 않는다.
- 1차 탐색: 조건별 200,000스텝, 공통 seed 1개. 비용을 줄여 후보를 좁히는 용도이며 최종 증거로 쓰지 않는다.
- 재현 확인: 기준과 후보를 공통 seed 3개로 200,000스텝씩 처음부터 학습한다. 선정 단계에서 쓴 seed도 명시한다.
- 기존 총 학습 길이 200,000은 유지하는 제안이다. 모두 학습이 덜 됐다면 확장 실험을 별도로 만들고 기준과 후보에 같은 예산을 준다. 잘 나온 조건만 더 오래 돌리지 않는다.
- 20,000 학습 스텝마다 평가 및 checkpoint 저장. 평가 스텝은 학습 예산에 넣지 않는다.
- 속도 비교를 위해 동일 장비·동시 작업 조건을 사용하고 학습 시간/평가 시간/전체 시간을 구분한다.

### 평가 목록

- 학습 seed 예시: 11/22/33. 튜닝용 교통 seed 예시: 1001~1005. 최종 검증용: 2001~2010. 실제 생성 파일과 버전을 함께 보관한다.
- 중간 평가: 전 경로 × 기준 부하 × 튜닝 seed 5개.
- 최종 평가: 전 경로 × 저/중/고 부하 × 최종 seed 10개. N=13이면 모델당 390회다.
- 평가 정책의 결정 방식은 고정하고 탐험 없이 평가한다. 정책 밖 HV 난수는 평가 목록으로 통제한다.
- 모든 실험에 동일한 차량 투입 일정·경로·초기 상태를 사용하되 AV 행동에 따른 후속 교통 변화는 허용한다.
- 어려운 사례를 평가에서 제외하지 않는다. 시작 조건을 만들 수 없거나 실행 오류가 난 사례는 학습 실패와 별도로 집계하며 누락시키지 않는다.

### 필수 지표

1. 경로별 및 경로 균등 평균: 완주율, 충돌률, 시간 초과율, 잘못된 출구 비율.
2. 충돌·완주율의 분모는 AV가 정상 투입된 평가 에피소드. AV 투입 실패와 미실행 수도 별도 표기.
3. 완주한 사례의 주행 시간 + 전체 사례의 목적지 진행률을 함께 표시한다. 성공 사례만 빨라진 결과를 전체 개선으로 표현하지 않는다.
4. 합류 대기시간, 지퍼 준수율(적용 가능 사건만 분모), 100m 준비 성공률, 실제 차선 변경 수, 실선 위반 수.
5. 급제동 횟수/주행 km, 저크, HV 전체 처리량·대기시간. AV만 빨라지고 HV를 막는 정책인지 확인.
6. 보상 항목별 합계와 활성화 횟수. 안전 게이트가 AV 명령을 막은 횟수도 기록.
7. 목표 성능 최초 도달 스텝과 시간. 제안 목표는 완주율 ≥90%, 충돌률 <5%를 3회 연속 평가에서 충족하는 것. 수업 충돌률 정의와 맞춰 확정하며 임의 기준임을 표기.
8. 목표에 도달하지 못하면 `미도달`로 표기한다. 전체 평균과 최악 경로를 함께 보고 어려운 경로의 실패를 숨기지 않는다.

TensorBoard에는 위 지표를 명시적으로 기록하는 코드가 필요하다. 기존 return 곡선만으로 원하는 성능 수렴을 판단하지 않는다. 가로축은 학습 스텝과 실제 경과 시간을 각각 본다. 보상식 또는 gamma가 다른 조건의 return/value loss 크기를 직접적인 성능 순위로 쓰지 않는다.

### 결과 표현

- seed별 원값과 평균·표준편차, 평가 횟수를 함께 기록한다. 3개 seed로 확정적인 일반화를 주장하지 않는다.
- 비율의 차이: 완주율 70%→80%는 +10%p. 상대 개선 +14.3%와 구분한다.
- 시간 감소: (기준−후보)/기준×100%. 기준이 0이면 상대 변화는 N/A.
- 가능하면 동일 route/load/seed 평가 쌍으로 비교한다. 성공자만의 시간 비교에는 선택 편향이 있음을 명시한다.
- 최종 선택은 안전·완주를 우선하고, 비슷한 수준이면 시간과 승차감을 비교한다. 학습 전 우선순위를 고정한다.

## 11. 수업 평가 기준에 따른 우선순위와 제출 조건

근거: [평가 문서](../project_materials/6_Project_Evaluation.md), [준비 문서](../project_materials/5_Project_Preparation.md), [컨설팅 문서](../project_materials/7_Project_Consulting.md). 원문은 변경하지 않고 보존한다.

| 수업 기준 | 설계에 반영할 증거/작업 |
|---|---|
| 실제 도로의 의미와 interaction | 실제 지도와 단순화 설명, 합류·분기·엇갈림 사례, AV 의사결정 연결 |
| 충분한 HV와 정상적인 흐름 | 평가 내 HV 수·교통량 기록, 비정상 정체·Teleport·오류 집계 |
| Collision Rate <5% | 충돌 평가 에피소드 수/전체 평가 에피소드 수와 원시 분모 기록. AV 충돌과 HV만의 충돌을 분리 |
| 목적지 완주 | 잘못된 경로·비정상 정지·무한 대기·시간 초과를 별도 실패로 보고 |
| 데이터 10^7개 이상 | 최종 정책의 별도 데이터 수집 단계와 검증·배포 예산 확보 |
| 전체 수행 과정 설명 | 단계별 문제→가설→수정→동일 조건 결과→한계, 효과 없는 실험도 기록 |
| 30초 이상 실제 주행 영상 필수 | 학습한 AV와 HV 상호작용, 도로 구조·목적지 주행이 보이는 SUMO 영상 확보 |
| 프로젝트 페이지 | GitHub 코드, 발표자료 PDF 접근 링크, Hugging Face 데이터 링크 제공. Canva 편집 링크만으로 PDF 요구를 대체하지 않음 |
| 최종 제출 | 코드·학습 모델·데이터·발표자료를 아이캠퍼스 과제함에 기한 내 제출. GitHub 업로드만으로 완료가 아니며 마감 이후 갱신 불가 |

평가 문서는 <5%, 소개·준비 문서는 ≤5%라고 표기한다. 전용 평가 문서의 더 엄격한 <5%를 작업 기준으로 사용한다. 완주율 90%, 3회 연속 통과, seed 3개는 **팀 실험 제안**이지 수업 지정 기준이 아니다. 충분한 HV의 수치 하한·전체 경로 수·필수 하이퍼파라미터 실험 개수는 명시돼 있지 않다.

### 실험 우선순위 조정

1. 필수: 실행 가능한 최종 맵, 안정적인 HV 흐름, AV 기본 완주, 평가·데이터 저장 검증.
2. 핵심 비교: R0/R-PREP/R-ZIP/R-BLOCK으로 합류 의사결정을 확인하고 필요시 조합 확인. R-SPEED/R-GAP는 기준 정책의 문제 진단에 따라 우선 시행 가능.
3. 학습률과 gamma 비교(H0/H-LR/H-GAMMA)는 같은 보상에서 시행하되 단순히 실험 수를 늘리기 위해 나머지 모든 보상 후보를 실행하지 않는다.
4. R-ARR/R-LC 등은 시간·결과에 따라 선택. 200,000스텝은 기존 계획의 비교 예산이지 수업 의무가 아니다.
5. 최종 정책 선정 후 최종 평가→대규모 수집→검증→영상·페이지·제출에 시간을 확보한다. ‘고민한 흔적’은 미실행 결과가 아니라 가설과 채택/보류 이유로 남긴다.

### 최종 데이터 수집 단계 D-FINAL

- PPO 학습 200,000스텝과 최종 제출 데이터 10^7개는 별개다. PPO rollout이나 TensorBoard 로그가 제출 데이터셋을 자동으로 구성하지 않는다.
- 준비 문서의 흐름대로 선정한 학습 모델을 collect_pomdp_data.py로 주행시켜 수집한다. 이전에 폐기한 HV 전문가 데이터나 수업 샘플을 새로운 최종 데이터로 합산하지 않는다.
- 원문은 ‘데이터 10^7개’의 계수 단위를 명확히 정의하지 않았다. 우선 고유 POMDP transition 10,000,000개로 용량·시간을 계획하되 교수/조교 확인 전 확정하지 않는다. NPZ와 JSONL에 같은 transition이 있으면 2개로 세지 않는다.
- 전체 규모 목표는 최종 데이터셋에 적용하는 계획이며 각 파라미터 실험마다 1천만 개를 수집하지 않는다.
- 모든 기본 항목을 보존: episode, t, observation, action_raw, action의 가감속/차선 raw·양자화·적용 여부, reward, terminated, truncated, state, detected_vehicles, 충돌/도착/변경 전후 차선 이벤트, next_observation, next_state.
- NPZ 고정 배열과 JSONL.GZ의 privileged state를 함께 검증한다. 다음 transition으로 다음 상태를 복원하는 경우 episode 경계를 넘지 않도록 검사한다.
- 문서의 observation 19차원 예시와 현재 코드의 31차원은 불일치한다. 임의로 19차원으로 축소하지 않고 실제 관측 스키마·단위·차원·버전을 기록한다. 기본 필드 보존과 확장 허용을 따른다.
- 중간 발표 이후 데이터 칼럼 scope 제한 예정이라는 문구가 있으므로 대규모 수집 전에 최신 공지/피드백을 다시 확인한다.
- 소량 파일럿으로 유효 transition/초와 bytes/transition을 측정해 잔여 수집 시간·저장 용량을 추정한다. 권한·SUMO 포트 충돌을 확인한 독립 worker별 shard로 나누고 중단·재개 시 중복을 검사한다.
- route/load/seed별 분포, 종료 원인, 결측·비유한값, next-state 정합성, 모델·맵·코드·설정 출처를 데이터 카드와 함께 공개한다. 실패 사례를 조용히 버리지 않는다.

## 12. 자동 설정 기록: 확인 결과와 최소 보완

현재 팀 main 코드 확인 결과:

- PPO: results/run_날짜_시각에 model.pt, training_log.csv, eval_log.csv, tb/를 저장하고 train.py·road_config.py·mdp_config.py를 snapshot_configs()로 복사한다. TensorBoard 초기화에 실패하면 CSV만 남을 수 있다.
- 스냅샷은 학습 시작이 아니라 train.py의 finally에서 모델 저장 후 실행된다. 정상 종료/Ctrl+C 등에 저장을 시도하지만 강제 종료·전원 장애·초기화 오류·앞선 저장 오류까지 보장하지 않는다.
- 실행 도중 원본 파일을 수정하면 메모리에서 사용한 설정과 종료 시 복사본이 달라질 수 있다. 현 코드로 비교할 때는 실행 중 설정 파일을 수정하지 않는다. 동시 실행도 서로 다른 코드 사본으로 분리한다.
- BC: 실행 인자, 데이터 경로, seed, 차원, 학습/검증 샘플·episode 목록 등을 config.json으로 저장한다. 전체 도로·환경 스냅샷과 동일하지 않다.
- collect_pomdp_data.py의 NPZ/JSONL은 주행 데이터다. PPO의 세 설정 파일 자동 복사 기능이 수집 결과에 그대로 제공되는 것은 아니다.
- test.py와 수집기는 현재 모듈의 설정을 import하므로 과거 model.pt를 지정했다고 과거 도로·보상 설정까지 자동 복원되지 않는다. 저장본과 평가/수집 환경의 일치 확인이 필요하다.

계획 변경: 새로운 JSON 설정 체계와 실험별 브랜치 생성을 필수로 두지 않는다. 기존 Python 설정+자동 스냅샷을 기본 기록으로 쓰고 GitHub에는 실험 목록·설정 차이·요약 결과를 연결한다.

향후 최소 보완(이번에는 코드 수정 없음): 실행 시작 시 실제 사용 설정과 세 파일을 보존하고 코드 SHA/dirty diff, SUMO·라이브러리 버전, seed, 맵 파일 체크섬, 실행 명령을 작은 manifest에 기록한다. 보상/환경 로직 자체를 바꾼 실험은 세 설정 파일만으로 복원할 수 없으므로 코드 버전도 반드시 연결한다. 수집 데이터에는 사용 모델 체크섬과 run 링크를 별도로 남긴다.
