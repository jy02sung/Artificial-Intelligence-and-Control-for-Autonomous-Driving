## 3. 무엇을 보여주고 무엇을 맡길 것인가

정적 지도+지정 경로+ego 자신의 위치 → 경로 관측 → PPO의 가감속/차로 명령 → 기존 동일 안전 검사 → SUMO.

지도에서 갈 수 있는 차로를 알려주되 명령을 생성하거나 덮어쓰지 않는다. `route_guard`, `route_guidance`, 교사 행동 주입, SUMO 자율 전략 차로 변경은 학습/평가 모두 비활성화한다. 기존 SUMO 속도/안전 동작과 환경 안전 게이트는 모든 조건에서 동일하게 보존하고 설정값을 저장한다.

정책 raw action과 환경 입력 action이 동일한지 매 스텝 검사한다. 양자화·안전 거부는 별도 기록하며 목적지 기반 override 횟수는0이어야 한다. 잘못된 차로로 가면 실패로 기록한다.

### 내비게이션 계산

- 사용 가능: 고정 도로 형상·차로 연결·지정 경로·ego 차로/위치. 실제 지도 기반 안내에 대응하는 정보다.
- 금지: 시야 밖 차량의 위치/속도, 미래 교통·궤적, 정답 행동, 경로 번호별 외운 지시표. privileged state는 분석 파일에만 저장한다.
- 전방300m 안의 첫 차로 준비 지점을 탐색한다. 일반 분기뿐 아니라5→4 감소 등 연결 가능한 차로가 제한되는 지점을 포함한다. 300m는 설계값이며 다음 단계에서 독립 튜닝할 수 있다.
- 다음 도로의 차로 번호를 현재 도로 번호와 직접 비교하지 않는다. 경로의 lane-to-lane 연결을 따라 역추적하여 현재 도로에서 해당 지점까지 이어지는 차로 집합을 계산한다.
- 짧은 연결도로가 연속되면 이전 도로부터 안내한다. 다음 두 개의 가까운 제약이 충돌하는 사례도 따로 검증하고, 정보가 불충분하면 임의의 정답 차로로 확정하지 않는다.
- 안내는 거리, 현재 차로 적합성/가까운 유효 차로까지 부호 있는 오프셋으로 표현한다. 거리 범위 밖/도착/내부 junction의 sentinel 의미를 명시한다. 정규화와 클리핑은 모든 조건에서 문서화한다.
- 기존 SUMO best-lane 값에 숨은 교통 정보가 섞일 가능성을 없애기 위해 새 안내는 정적 연결 그래프에서 계산한다. N0의 기존 best-lane 값은 그대로 보존하여 대조군임을 명시한다.

### 관측 조건: 차원과 모델 구조 동일

현재31개 기본 관측+6개 IC 관측=37차원이다. 아래 모두37차원, 동일 네트워크 크기로 비교한다.

| 조건 | 바꾸는 부분 | 고정하는 부분 |
|---|---|---|
| N0 | 없음: 현재 legacy 관측 | 기존 best-lane, 제한적인 분기 거리/방향 포함 |
| N1 | 기존 IC 관측 앞3슬롯을 정적 경로 안내(현재 연결 적합 차로 방향, 전방 준비 지점 거리, 준비 목표 오프셋)로 대체 | 기본31개 및 제한속도/램프/지퍼3슬롯 |
| N2 | N1+기본 관측의 차로 연결성5개를 지정 경로 기준으로 계산 | 나머지 동일 |

N1은 경로 안내 표현 묶음의 효과, N2-N1은 차로 연결성 의미 변경의 추가 효과를 비교한다. N1의 세 세부 입력 각각이 원인이라고 분리 주장하지 않는다. N0와N1의 차이는 동일 차원이라도 의미가 다르므로 체크포인트/수집 데이터에 observation_schema를 반드시 기록한다.

현재 도로가 실선이라 차선변경이 불가능하더라도 안내 자체는 목표를 보여줄 뿐이다. 실선을 없애거나 안전 게이트를 우회하지 않는다. 차선변경 가능 여부 입력은 이번1차 관측 비교에 추가하지 않고 필요할 때 별도 조건으로 분리한다.

S3 이후 학습량은 S1/S2의 수렴 곡선을 보고 **실행 전에** 동일 예산으로 확정한다. 기존200k를16경로 학습에 충분하다고 가정하지 않는다. 현재 요청은 설계이며 이 문서로 무기한 자동 학습을 시작하지 않는다.

## 5. 고정 파라미터와 평가 분리

기존 R0 실행 스냅샷: lr=0.0003, gamma=0.99, n_steps=2048, epochs=10, minibatch64, GAE0.95, clip0.2, hidden[256,256], hybrid PPO. 세부값은 [설계 JSON](experiments/ic-navigation-plan-v1.json)에 저장한다. reward·가감속·차선변경 안전·900초 제한·dt0.2·맵·출발 조건은 쌍별로 동일하다. 보상 개선과 lr/gamma 실험은 관측 비교 이후에 각각 별도로 진행한다.

- 학습seed:11/22/33. 초기화와 환경 추출 seed를 구분해서 저장한다.
- 검증seed:20001~20020. 진행 상황 확인 및 후보 선택에만 사용.
- 최종평가seed:30001~30100. 후보 고정 후 평가하고 이 결과를 보고 다시 튜닝하면 새 holdout을 사용한다.
- 출발 조건: 실제 삽입·동일 행동 제약 통과가 확인된 차로/속도/위치 조합을 사전 목록으로 고정한다. 실패한 정책에 유리한 시작점만 고르지 않는다. 실패한 삽입도 별도 실패 건수와 원래 할당 수를 공개한다.
- 무교통에서 seed만 바꿔 같은 출발/결정적 정책을 반복하면 같은 궤적이므로 독립100시험으로 과장하지 않는다. 출발 조건을 실제로 변화시켜 seed와 함께 기록하고 고유 시나리오 수를 보고한다.
- 최종 평가: 정책seed별·경로별100episode. 팀 목표 완주≥95%, 수업 기준 충돌<5%(100건이면 최대4건). 경로별 및 전체를 모두 보고하고 전체 평균으로 실패 경로를 가리지 않는다.
- 성공: 지정 출구 도착+충돌0+텔레포트0. 단순 사라짐/잘못된 출구는 성공 아님.
- 실패 분류: 삽입 거부, 충돌, 잘못된 출구, 경로 미연결 차로 끝 정지, 올바른 차로에서 제동/정지, HV 대기, 움직이는 중 시간초과, 시뮬레이터 오류. 시간초과를 임의로 성공 처리하거나 종료 시간을 조건별로 늘리지 않는다.

통계적95% 신뢰 하한 보장은 별도 문제다. 여기의95%는 관측된 완주율 목표이며 seed3개/소수 smoke 시험으로 신뢰구간 보장을 주장하지 않는다.

## 6. 교통과 제출 데이터

무교통 성과만으로 최종 평가를 마쳤다고 하지 않는다. HV의 네 제어기 비율·버스 비율·각 진입부 수요·지퍼 설정·위반2%를 실제맵에서 검증한 뒤 모든 비교에 동일하게 동결한다. 기본수요가 비정상 병목을 만들면 HV 전용 근거로 수정하고 새로운 환경 버전으로 기록한다.

데이터에는 기존 observation/action_raw/next_observation/reward/terminated/truncated/episode/t/lane_change/detected_xy/detected_offsets 및 privileged state를 보존하고, route·정책/맵/관측스키마 해시·목표 차로/거리·정책명령/환경명령·거부사유·실제 변경·종료 원인을 추가한다. privileged state가 모델 입력에 섞이지 않는지 검사한다. transition 고유키(run,episode,t), 중복·누락·해시를 검증한다. 10^7은 우선transition 기준으로 계획하되 채점상 정확한 집계 단위는 공개 요약 문구만으로 보증하지 않는다. 이전 팀원 답변에서도 별도 설명은 없었다.
